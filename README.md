# Luz Design

为中文产出定视觉标准，画产品界面与原型的外观，做海报与品牌视觉，排报告、Excel、Word 等文件的版式。

## 能做什么

- **视觉标准**：配色从官方色板按行业气质取阶，附 25 个行业主题（含面向企业工具后台的石墨主题），每个主题都有浅色与深色两套色板（`make_dark.py` 推导，`check_contrast.py` 核对）；一条统一的中文字体栈、各类产出的字阶与七级字体角色（字重 400/600/700）；扁平图形（2 像素线性与双色图标、多层扁平插画）与五级层级的立体感（双层阴影、发丝线、按钮底边、遮罩）、圆角、间距与动效；对比度按无障碍指南 2.2，另有点击区域、视口与安全区、小程序字号档位、中文排版、深色与浅色两套主题（产品前端同时提供并跟随系统，阅读页、海报与文件只做浅色）与现代样式特性的兼容状态；主题可导出成设计令牌文件（浅色与深色取值同在一个文件）交给开发。其他 Luz 技能的界面都以此为准。
- **产品界面与原型的视觉**：后台、小程序、网站、智能体界面的构图与排布、卡片与按钮等组件的外观、图标、配图、动效、主题，以及可交互原型的全部外观，都在系统技能给出的功能清单（页面、标签栏、组件与按钮动作）之上画出来，不增删功能；划线见 `references/ui-ownership.md`。
- **界面项目的路径与页面范式**：做整个界面项目先读规则卡 `design-path`，它给出从接收到交接的十个阶段（每阶段的产出、检查与该读的规则卡）、思考工具和偏离说明的写法，`design_path.py` 生成可粘进会话 BRIEF 的检查表；首页与常见页面的范式（金刚区、信息流、便当、顶部与侧边分类等）、入口归属与去重读规则卡 `page-patterns`，`page_pattern.py` 拿到系统技能给的入口表 `entrances.json` 和功能清单后依次生成首页简报与方案、检查方案和成品页，不增删功能与入口。
- **原型参考实现与组件模板库**：产品开发阶段交付的前端界面 HTML 做成三栏单文件的可点原型（页面目录、外观配置、场景开关、逻辑面板、页面栈导航，多个系统一个系统一个页签）。`references/prototype-templates/` 是原型参考实现（引擎、小程序与后台模板、多系统外壳、规格校验与生成器 `build_prototype.py` 与 `build_prototype_suite.py`，三份小程序示例与两份后台示例），`references/component-library/` 是 303 个带编号的组件模板库（登记为可选库 `luz-kit`，浅色默认，深色已适配）。它们只是参考，不是模板：机制可复用，页面清单、首页组成与入口由功能清单和行业决定；怎么用、交付要满足什么读规则卡 `prototype-reference`。
- **海报与品牌视觉**：活动海报、品牌主视觉、宣传图，规定安全区、文字层级、缩略图辨识与版权边界；印刷海报另有出血、色彩与分辨率；照片可交给本机图像生成服务。
- **Excel 与 Word**：Excel 单工作表、12 磅起、无序号、分组名纵向合并、一格一事实；Word 按合同、方案、报告、会议纪要、公文分类排版。两者都由脚本直接生成。
- **其他文件**：阅读型网页、演示文稿、PDF、Markdown 的标题、字号、表格与图表规则。
- **自动检查**：拦截小字号、多字体、浅色主题里的大面积深色、装饰渐变与立体效果、图标混用、文字头像、表格合并错误、合同缺项与占位文字；PDF 用 `check_pdf.py`（字体嵌入、文字层、书签，可选标签与语言、印刷出血）加逐页渲染核对；演示文稿核对 16:9、页边距、标题与替代文字。页面还在真实浏览器里按浅色与深色各审计一遍（`audit_rendered.py --scheme dark`）。其他 Luz 技能也用它检查自己的页面。
- **经验沉淀**：记住用户偏好、有效的配色与字阶、踩过的坑，下次调用先查再做。

## 适合与不适合

| 适合交给本技能 | 改用 |
|---|---|
| 配色、字体、图标、间距等视觉标准 | — |
| 后台、小程序、网站、智能体界面的视觉与排布，原型的外观 | — |
| 海报、品牌主视觉、宣传图 | — |
| 报告、Excel、Word、演示文稿、PDF 的版式 | — |
| 系统方案、功能清单、界面的功能结构与流程（页面、入口、标签栏、组件清单、按钮动作）、原型的行为与数据、硬件选型 | [Luz-System](https://github.com/luzern0414/Luz-System) |
| 后端、接口、数据库、部署上线 | [Luz-Dev](https://github.com/luzern0414/Luz-Dev) |
| 文章、文案、协议条款等文字本身 | [Luz-Writing](https://github.com/luzern0414/Luz-Writing) |
| 网页检索与采集 | [Luz-Crawl](https://github.com/luzern0414/Luz-Crawl) |

## 快速开始

1. 把整个目录放进 Agent 的技能目录（例如 `~/.claude/skills/luz-design`）。
2. 安装 Python 3.11 及以上，以及生成与检查文件用的库（表格、Word、演示文稿、元素拼板切图）：

   ```bash
   pip install openpyxl python-docx python-pptx pillow numpy
   ```

   核对 PDF 时另装 `pymupdf`；校验脚本读技能说明的头部信息时用到 `pyyaml`（可选）。

3. 需要调研配色或规范时，另装 [Luz-Crawl](https://github.com/luzern0414/Luz-Crawl)；图片生成是可选能力，需要本机的图像生成服务。

然后直接提需求，例如：

- “做一张健身房周年庆的活动海报。”
- “把这份调研结果整理成一个单工作表的 Excel，类别合并、加浅色底。”
- “按这些条款排一份设备采购合同的 Word。”
- “这份方案的配色和字号按规范调整一下。”
- “按系统技能给的功能清单和入口表，把小程序的首页和页面设计出来。”

## 工作方式

1. **先读规则卡**：`context.py <任务类型>` 一次给出这类任务的你的偏好、相关教训、规范原文、该用的工具和必须通过的检查；模板和生成脚本只是骨架，内容以规则卡为准。
2. **收集事实**：只记录用户给出的目的、对象、渠道、精确文案、尺寸与格式；缺文案或格式就先停下来问。
3. **建会话**：每个任务一个编号目录，工作文件放在 `raw/`，最终只交付一个文件。
4. **调研**：配色、字体或文件格式需要依据时，按 Luz-Crawl 的调用协议查官方色板、设计体系和标准，并写明依据。
5. **出稿**：视觉稿汇总在一个总览页里，**等用户批准**后才算定稿；文件先定类型，再按类型排版并导出。
6. **检查与交付**：在 BRIEF 里写明采用了哪些规则；表格和 Word 生成后自动检查，网页用检查脚本复核，零错误才交付；没写“采用的规则”的会话不能发布；改动过的产出需要重新批准。
7. **沉淀**：结束前把新的偏好、有效信息和教训写回经验库。

## 经验沉淀

Luz-System、Luz-Design、Luz-Dev、Luz-Writing 四个技能用同一套经验沉淀：经验库是 `experience/notes.json`，分偏好、教训、有效信息三类，按主题键更新而不是堆积；开始时用 `scripts/experience.py search` 查，结束前用 `note` 写。字段、上限与清理规则见 SKILL.md“每次调用后沉淀”。仓库公开，手机号、邮箱、微信号、个人目录路径、密钥与客户名称都不写进去。

本仓库另有整理好的配色、字阶、视觉与文件规则库 `patterns.json`（最多 200 条，用 `add` 批量写入）和来源库 `sources.json`。

## 目录结构

```text
SKILL.md        技能入口：分工、路由、规则摘要、每次调用后沉淀
WORKFLOW.md     各阶段的进入条件与停止条件
references/     视觉设计规范、文件设计规范、界面实现参考（价格、角标、券面、不规则卡片与浮层效果的画法）、页面范式库（page-patterns.html，数据在 page-patterns.json）、设计路径与思考链（design-path.html，数据在 design-path.json）、原型参考实现与组件模板库的规则页（prototype-reference.html）、组件模板库（component-library/）、原型参考实现（prototype-templates/）、界面职责划分（ui-ownership.md）、行业主题库、UI 套件（含交易与营销界面示例 commerce-kit）、生图提示词与会话模板
experience/     经验库：用户偏好、教训、配色与字阶等模式、来源，以及生成的目录页
scripts/        文件、PDF 与对比度检查、设计令牌导出、Excel 与 Word 生成、页面范式（page_pattern.py）与设计路径（design_path.py）、原型生成（build_prototype.py、build_prototype_suite.py）与组件模板库的构建检查、会话、发布、经验库、校验与测试
agents/         Agent 平台配置
```

## 七个技能的分工

| 技能 | 负责 |
|---|---|
| [Luz-System](https://github.com/luzern0414/Luz-System) | 系统设计：软件方案、功能清单、界面的功能结构与流程、硬件选型 |
| **Luz-Design**（本仓库） | 视觉标准、产品界面与原型的视觉、海报与品牌视觉、文件排版 |
| [Luz-Dev](https://github.com/luzern0414/Luz-Dev) | 后端、接口、数据库、部署与上线 |
| [Luz-Writing](https://github.com/luzern0414/Luz-Writing) | 文章、文案、协议等文字内容 |
| [Luz-Crawl](https://github.com/luzern0414/Luz-Crawl) | 真实浏览器检索与采集 |
| Luz-Ops | 验收测试、发布门禁、监控、备份与回滚 |
| Luz-Project | 完整项目目录、阶段路由、审批与汇总 |
