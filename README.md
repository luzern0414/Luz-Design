# Luz Design

面向中文产品的前端设计技能（Agent Skill）：把一句需求变成**有调研依据、经人工批准、可在浏览器里操作的产品设计**，覆盖网页管理后台、小程序、智能体界面和网站，也负责报告、表格、Word、演示文稿等交付文件的版式。

## 能做什么

- **系统设计**：确认模块范围 → 用真实浏览器调研同类产品 → 写系统架构（角色、页面、动作、状态机、追溯）→ 输出系统设计网页。
- **视觉与原型**：按行业气质定主题色，产出视觉方向、视觉稿，以及小程序与后台一体的可交互原型，交付为一个自包含的 HTML 文件。
- **交付文件**：报告与规范网页、单工作表 Excel、合同 / 方案 / 报告 / 会议纪要等 Word 文档、演示文稿，都按统一的字体、字号、配色与结构规则排版。
- **质量把关**：每个阶段都有人工批准记录（含文件哈希），并用脚本检查字号、字体、配色对比度、装饰、头像、图标、表格合并方式、合同要素等常见问题。
- **经验库**：每个项目沉淀调研来源、功能、交互流程、组件、配色与规则，下一个项目先查库再调研。

## 设计规范的结构

规范按层次组织，先通用、后分端：

| 规范 | 内容 |
|---|---|
| 通用设计规范 | 七层通用标准：设计架构 → 功能架构 → 信息架构与导航 → 页面与版式 → 组件 → 视觉基础（配色、字体字号、图标、圆角阴影、动效）→ 文案；每层末尾列出四个端的差异 |
| 网页管理后台 / 小程序 / 智能体 / 网站 | 用同样的七层标题，只写各端细则，例如后台的数据驾驶舱排序、小程序的页面栈与返回、智能体的审批与接管、网站的首屏与转化 |
| 系统设计 / 视觉设计 / 系统功能列表 / 文件设计 | 各工作模式的流程、门禁与交付格式 |

几条贯穿全部产出的原则：扁平线性风格（不用立体、渐变、玻璃效果）；一个产品只用一条字体栈，网页文字不小于 12 像素；配色取自官方色板并满足无障碍对比度；不同对象不共用同一个图标；界面里不写说明文字和多余入口。

## 典型用法

把本目录放进 Agent 的技能目录后，直接用自然语言提需求，例如：

- “做一个健身房小程序和门店后台的系统设计和可交互原型。”
- “给这个 SaaS 产品设计官网首页和价格页。”
- “把这份调研结果整理成一个单工作表的 Excel，类别合并、加浅色底。”
- “按我们的条款写一份设备采购合同的 Word 版。”

Agent 会按规范先确认范围、做调研、请你批准架构，再出设计与原型；每个产出放在独立的会话目录里，最后只给你一个最终文件。

## 目录结构

```text
SKILL.md          技能入口：路由、规则摘要、工作顺序
WORKFLOW.md       各阶段的进入条件与停止条件
references/       设计规范网页（9 份）、会话模板、主题色库、开发交接契约、生图提示词模板
experience/       经验库：调研来源、可复用模式与目录
scripts/          建会话、发布、校验、文档检查、Excel 与 Word 生成等脚本
agents/           Agent 平台配置
```

## 依赖

- Python 3.11 及以上；文件检查用到 `openpyxl`、`python-docx`，原型截图与浏览器验收用到 Playwright。
- 调研依赖 [Luz-Crawl](https://github.com/luzern0414/Luz-Crawl)（真实浏览器采集）。
- 图片生成为可选能力，需要本机的图像生成服务。
- 默认把产出写到 `D:\Codes\skill输出\Luz-Design\`，可在 `scripts/new_session.py` 中修改。
