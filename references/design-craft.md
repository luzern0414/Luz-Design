# 审美工作法（怎么把界面从“能用”做到“高级”）

本页是工作方法和自检工具，不新增数值规则：数值一律以 `visual-design.html` 与 `themes.json` 为准，两边冲突时以规范页为准。凡是需要放宽规范的做法，写进 BRIEF 的“待裁定”，由用户决定。

## 1 先记住：高级感从哪来

高级感不是某一种效果，而是五件事同时成立：**层级清楚、全局一致、克制、素材好、细节完整**。按投入产出比排序：

| 顺序 | 因素 | 为什么 | 做法在本页第几节 |
|---|---|---|---|
| 1 | 层级与留白 | 一眼能看出重点；拥挤和平铺是“廉价感”的头号来源 | 4、5 |
| 2 | 一致性 | 字阶、间距、圆角、阴影、图标线宽全局一套，显得有设计系统 | 3 |
| 3 | 克制的配色 | 中性色占大头，一个主色、一个点缀色、按比例使用 | 3 |
| 4 | 素材质量 | 商城、内容类产品里权重最大；好的实拍或同风格 3D，抵得上所有 UI 细节 | 6 |
| 5 | 状态与细节 | 空、加载、错误、按压、焦点、深色、长文本是否齐全，决定“像不像成品” | 7 |
| 6 | 动效 | 短、自然、只在有意义的地方；掉帧会让其他一切失效 | `motion-recipes.md` |
| 7 | 材质（玻璃、渐变、光影） | 最后一层点缀；基础不稳时加材质只会更乱；受风格作用范围限制 | `style-boards.json` |

## 2 起手：个性形容词与反目标

动手前写下三样东西（写进 BRIEF，不写进成品）：
1. **三个个性形容词**（如“温柔、有仪式感、克制”），所有后续选择都要对得上其中至少一个；
2. **三条反目标**（如“不要塑料感、不要满屏粉、不要促销味”），它们比正向目标更能防止跑偏；
3. **一个参照比喻**（“像一本花艺杂志”“像一把好用的瑞士军刀”）。
然后在 `style-boards.json` 里按五个旋钮（暖冷、沉静活跃、随性庄重、疏密、纯平质感）挑 2–3 块最接近的板，写明选它的理由和不选其他板的理由。

## 3 八个可量化的一致性规则（做完用 `teardown.py --lint` 复核）

1. **字阶不超过 7 档**，相邻档比例接近同一个模块比（1.125–1.333），字重只用 400 / 600 / 700（700 只给 22 以上）。
2. **间距落在 4 的倍数上**，常用 8 / 12 / 16 / 24；组内间距不超过组间间距的一半（亲密性）；**相邻档要拉开**（至少约 1.33 倍，12 与 14 这样看不出差别的值不同时使用，否则分组会含糊）；设计稿与代码用同一种量法（都量相邻元素的边界框，或都量字高），否则稿子转成代码会走样。
3. **圆角不超过 4 种**，且嵌套时内层圆角 ≈ 外层圆角 − 内边距（外 12、内边距 4，则内层 8）。
4. **阴影只有一个光源方向**（只向下或统一方向），层级不超过 4–5 级，卡片第 1 级、浮层第 3–4 级。
5. **主色面积小于约 10%**；中性色占 60% 以上；点缀色不与主色争夺（见 60-30-10）。
6. **正文对比度 ≥ 7:1（本技能标准）**，任何文字 ≥ 4.5:1；非文本图形 ≥ 3:1。
7. **文本块左边缘的对齐线不超过 6 条**；同一列的元素左对齐到同一条线，数字右对齐且等宽。
8. **图标一套线宽、一套圆角**，同一对象处处同一个图标；同组图片同一比例、同一调色。

## 4 层级：四根杠杆，一屏三个重点

层级靠四根杠杆调：**大小、字重、颜色深浅、留白**。一屏最多三个视觉重点（品牌或主任务一个、关键信息一个、一个行动），其余都退到次级。

- 先放大重点，再缩小其他，而不是给所有东西都加粗。
- 弱化比强化更有效：把次要信息的颜色从 `ink` 降到 `ink2`/`ink3`，比加大重点更干净。
- **眯眼测试**：把页面截图模糊到文字读不出（高斯模糊 8px），还能看出重点在哪、分组在哪，才算层级成立。
- **五秒测试**：给别人看 5 秒，问“这页让你做什么”，答不出就是层级失败。

## 5 节奏与留白

- 竖向节奏用同一个基准（4 或 8）连续排下去，段与段之间的间距比段内大一档。
- 留白不是“空着”，是“分组”：相关的靠近，无关的拉开。想让某块显得高级，先给它更大的周边留白。
- 留白比例经验范围：移动端 25%–65%；低于下限显得挤，高于上限显得空洞。
- 满幅大图与留白交替，节奏比每块都一样大小更有呼吸。营销区可错落（一大两小、出框），功能区必须对齐等高。

## 6 素材决定上限

选素材的顺序：**实拍 > 同风格生成的真实感摄影 > 同风格 3D/插画 > 矢量占位**。

| 场景 | 推荐 | 原因 |
|---|---|---|
| 商品图、头图 | 真实感摄影（实拍优先；没有实拍用 Imagegen 生成，见 `imagegen-playbook.md`） | 质感与可信度来自真实光影 |
| 入口图标、空状态、结果页 | 同一套 3D 或扁平插画，一次生成 4×4 拼板 | 风格统一，一对象一张 |
| 主视觉装饰 | 单个半透明玻璃或软陶物体，透明底 | 提升质感又不抢内容 |
| 后台 | 不用装饰图，用线性图形与数据图 | 降噪，扫读效率优先 |

规则：同一组图同一光线、同一背景、同一取景比例；统一调色（同一色温与饱和度）；图片永远有圆角与留白，不贴边（满幅头图除外）。**占位图不交付**：如果只能用矢量占位，在 BRIEF 里写明并告知用户“这是占位，上限很低”。

## 7 细节检查（“成品感”一次过）

逐项勾，每项都要在浅色与深色、390 与桌面各看一遍：
- 对齐：图标与文字光学居中；行高统一；数字等宽；货币符号与小数缩小一档。
- 状态：按压、禁用（写原因）、加载（骨架或按钮内转圈）、空（插画加一句话加下一步）、错误（原因加怎么办）、成功。
- 边界数据：超长文案（截断加省略号，不撑破）、极短文案、0 与超大数字、缺图、慢网、断网。
- 焦点：文本框只把 1px 边加深到次要文字色；按钮键盘 Tab 才出现 2px 深色轮廓。
- 触控：可点元素 ≥ 44×44（视觉小的用透明点击区放大）。
- 深色：不是反相，更暗的底、更亮的前景、品牌色取同色相更亮一阶。
- 减少动态效果：位移改淡入或直接切换。

## 8 “廉价感”症状与修法

| 症状 | 成因 | 修法 |
|---|---|---|
| 一屏到处都是重点 | 层级杠杆全拉满 | 只保留三个重点，其余降一档（颜色、字重） |
| 看着乱但说不出哪里 | 对齐线太多、间距随意 | 统一到 ≤6 条对齐线、4 的倍数间距 |
| 颜色花 | 每块一个色相 | 一个主色、一个点缀，其余中性 |
| 边框和阴影到处是 | 用线框代替留白 | 去掉边框，靠留白和第 1 级阴影 |
| 字号一堆 | 临时调大小 | 回到字阶，不够就合并相近的档 |
| 图标风格不一 | 来源混杂 | 控件图标统一 2px 线性；入口图标同一套 |
| 图片风格不一 | 不同来源、不同调色 | 同组同光线同背景同比例，重新生成或统一调色 |
| 默认组件感太强 | 只换了颜色 | 统一圆角、阴影、字阶、间距，换成品牌令牌 |
| 文案挤满 | 想解释所有东西 | 一个目的一句话；删除测试：删了不影响理解就删 |
| 空洞 | 留白变成空白 | 用大图、数字或品牌元素承接留白 |
| 动效花哨 | 到处加动画 | 只保留说明“从哪来到哪去”的动效，≤300ms |

## 9 商用小程序与后台系统的差别

- **小程序**：单手、拇指区、首屏要快、图片驱动；主色面积小、价格突出；营销区可错落、功能区对齐；标签栏 2–5 个；每个页面一个主任务。
- **后台**：扫读效率第一；降噪（少边框、少颜色、状态用小点加文字）；表格对齐规则统一；核心指标左上第一落点；默认显示最需要处理的子集；一致性高于创意。

## 10 审美评审评分表（交付前自评，不够就迭代）

对 390 与桌面、浅色与深色四张截图各打分，取最低值。0 = 明显问题，1 = 勉强，2 = 合格，3 = 出色。

| 项 | 问题 |
|---|---|
| 层级 | 一眼看出三个重点吗？眯眼测试通过吗？ |
| 留白与节奏 | 分组清楚吗？留白比例在范围内吗？ |
| 一致性 | 字阶、间距、圆角、阴影、图标是否各只有一套？ |
| 配色 | 主色面积、中性色占比、对比度是否合格？ |
| 素材 | 图片同光同调同比例吗？有占位图吗？ |
| 排版 | 对齐线、行长（约 40 字、≤48）、数字等宽？ |
| 状态 | 空、加载、错误、禁用、成功齐全吗？ |
| 动效 | 时长在令牌内、可打断、有降级吗？ |
| 深色 | 是不是单独设计的，不是反相？ |
| 个性 | 看得出三个形容词吗？踩中反目标了吗？ |

规则：**任一项为 0 不交付；总分低于 20/30 不交付**；评分写进 BRIEF 的“采用的规则”，并附 `teardown.py --lint` 的提示条数与处理结果。

## 11 训练审美：拆解 → 临摹 → 对比 → 写规则

1. **拆解**：挑一个你觉得好的真实页面，用 `teardown.py` 或手动量出字阶、间距、圆角、色板、留白，写成一张表。
2. **临摹**：不看原图细节，只凭这张表在 HTML 里重画一遍。
3. **对比**：把你的版本与原页面叠放，找差异；每个差异问“它为什么这么做”。
4. **写规则**：把学到的一条写成可检查的规则，放进 `experience/patterns.json`（视觉规则）或 `notes.json`（lesson）。
每个项目至少做一轮，结论写进 BRIEF 的“本次沉淀”。

## 12 迭代循环（“删除测试”之外）

1. 做粗版，只用中性色和字阶；
2. 加主色与素材；
3. 做眯眼测试与评分，找到最低分的项；
4. 只改最低分的项，其余不动；
5. 回到 3，直到没有 0 分且总分 ≥ 20/30；
6. 最后一轮才加动效与材质，并再测一遍性能与对比度。
