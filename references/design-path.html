设计路径与思考链

适用范围

产品前端（小程序、网页后台、网站、智能体界面）及其原型，从拿到系统技能交来的界面功能，到交付视觉规范的整条路径：十个阶段，每阶段怎么想、做什么、交什么、查什么、哪里可以不照做。划线见 references/ui-ownership.md：系统技能决定有什么、做什么，本技能决定长什么样、怎么排、怎么动，并且不增删。数据在 references/design-path.json，查询、检查表与偏离记录用 scripts/design_path.py。路径是思考的顺序，不是填空题。

工作流程

P0 接收与判定 → P1 参照与研究 → P2 入口与信息架构核对 → P3 页面清单与范式选择 → P4 视觉方向与令牌 → P5 组件库与模块映射 → P6 细节系统 → P7 动效与状态 → P8 原型与验证 → P9 交接与沉淀

  • 往回走：P2 发现入口表有错，退回系统技能（项目模式走需求变更台账）；P8 最低项出在方案层，回 P3 或 P4；用户否决方向，回 P4。
  • 可并行：P5 与 P4 的后半，P6 与 P7；P1 的检索在 P0 完成后立即开始。
  • 页面范式库只在 P2、P3 用，规则强度三档、偏离说明、精简五问沿用它的 show method。
  • 每阶段结束就勾检查表（design_path.py checklist），产出和偏离说明当场写进 BRIEF。

核心规则

一、怎么用这条路径

  • 强度三档：must 违反即退回；default 可偏离但要写偏离说明；hint 按情境取舍。id 可直接写进 BRIEF 与偏离说明；想创新走 when-to-innovate。
编号与强度要求
function-first
must		功能先于外观：不增删系统技能批准的页面、入口、标签栏项数、组件、按钮动作；画不下就退回。
hard-floor
must		七条底线不偏离，也不拿来换个性：
1. 对比度达标（正文 7:1，文字 4.5:1，控件 3:1），触控目标不小于 44×44
2. 文本框聚焦只加深 1 像素边，不出蓝框与发光；按钮仅键盘聚焦出 2 像素深色轮廓
3. 加载、切换、换主题不跳位不闪白；动画有减少动态效果分支
4. 浅色深色两套，深色单独设计不是反相，默认跟随系统
5. 控件全是所选组件库的真实组件，不手写控件
6. 控件图标 2 像素线性矢量，一物一图标
7. 一个主色，不用渐变按钮，颜色只取所选主题与共用状态色
approval-gates
must		用户确认门：风格方向未经用户确认，不调 Imagegen、不改页面代码、不发布；脚本不代批。
tiers-and-deviation
must		must 违反即退回；default 可偏离，须写偏离说明；hint 按情境取舍；must 不偏离。
vocabulary-not-sentence
default		范式是词汇不是句子，先问题后查表：选范式、组件、颜色前，先写它要回答的用户问题，再查库，留一行理由。
innovate-within-budget
default		记忆点预算：每个项目 1–3 个，后台 0–1 个，来自品牌与场景，不拿 must 与底线去换。
evidence-over-memory
default		参照来自真实采集与量化，不凭记忆；借属性不借成品。
fix-lowest
hint		评审只改最低项，改一处复评一次。

两个做法冲突时的裁决顺序，靠前的赢：功能，无障碍与稳定，一致，清晰与密度，美观，个性。逐层含义和用法见思考工具 conflict-order。

二、十个阶段

P0 接收与判定

目的把用户原话和系统技能的界面功能变成设计简报与约束清单；本阶段不画。
思考链1. 哪一端、哪一类产品？决定读哪几张规则卡、用哪套字阶、要不要首页范式。
2. 写一句话定位：给谁、什么场景、完成什么、比同类多（少）什么。（见 positioning）
3. 用户回来做的第一件事是什么？新用户、回访、空数据各是什么？（见 first-landing）
4. 硬约束（品牌色、标志、平台限制、合规）与软偏好分开，硬的每条标来源。
5. 系统技能的功能里有画不下、重复、越界的吗？记进退回清单，不自己改。
6. 缺精确文案、品牌素材、渠道？核心事实缺失就停下来问，最多 6 问。
按序做context.py list → 规则卡 design-direction → experience.py search → design-prompts.md → new_session.py
产出1. BRIEF.md：定位、三状态首要事、硬/软约束、页面标签栏组件数量
检查1. 硬约束与软偏好分两栏，硬的有来源
2. 页面、标签栏项、组件数已写成数字
3. 规则卡名与命中的经验 key 写进“采用的规则”
可偏离处1. 已有品牌规范：性格词摘自规范，反目标仍要写

P1 参照与研究

目的用真实同行取代记忆，量出行业底线与差异空间，决定借什么、拒什么。
思考链1. 要回答哪 2–3 个设计问题？研究围着它们做，不泛看。
2. 哪 3–5 个同行最像我们的用户与场景？至少一个更大，一个场景相同品类不同。
3. 它们共同做对了什么（行业底线）？差异在哪（品牌空间）？哪一点放到我们的内容与用户上会失效？
4. 只许借一件，借哪件？写成“借它的某属性，因为……”，同时写不借什么。
5. 取不到的页面记进缺口，不用旧知识冒充采集。
按序做crawl_preflight.py → reference-research.md → teardown.py
产出1. 01-research/teardown-compare.md：同行指纹表，末列本次取值与理由
2. BRIEF.md：借用与拒绝清单、缺口
检查1. 前置检索 check 通过
2. 指纹表至少 3 个产品，每行有本次取值
3. 借用、拒绝各至少 2 条，缺口写明范围
可偏离处1. 找不到同行：取相邻品类加官方规范，指纹表可缩到 2 个并写缺口
2. 无网络：写“未做本次检索”，只用经验库已验证的取值

P2 入口与信息架构核对

目的确认每个功能只有一个家、家在对的区域；是核对不是重做，有错退回。
思考链1. 对入口表每一行答入口归属三问：哪一类？多高频？已有家了吗？落的区域允许吗？（见 entry-ownership）
2. 同一目的地在这页出现几次？标签栏已有的丢掉，只留一个载体。
3. 标签栏几项？超出 2–5 项退回系统技能。
4. 并列核心任务够 5 个吗？不够用入口大卡，不硬凑金刚栅格。
5. 被合并或拒绝的功能去了哪、为什么？记下来，不是删除。
6. 入口表本身有错（账户类放首页、门店不在顶部）吗？附规则 id 退回，不自己改。
按序做page_pattern.py show method → page_pattern.py recommend → page_pattern.py brief → page_pattern.py plan → page_pattern.py check
产出1. 02-visual/page-pattern/spec.json：首页方案（modules、rejected、deviations）
2. BRIEF.md：退回清单
检查1. page_pattern.py check 零 must 违反
2. 被拒功能每个有去处与原因
3. 页面、入口、标签栏数与 BRIEF 一致
可偏离处1. default 规则可偏离，写偏离说明；must 不偏离

P3 页面清单与范式选择

目的给每页写蓝图：第一件事、区块、范式、组件、状态，选范式的理由留痕。
思考链1. 这一页用户要做的第一件事是什么？只许一件，它就是第一落点。
2. 信息分主角、配角、细节三档；一屏只有一个视觉重心。
3. 每个区块回答哪个用户问题？答不出就删，两块答同一问就合并。（见 density-test）
4. 选范式前答四问：同质吗？浏览还是执行？数量与信息量？有没有图？再读候选范式的“选它前要问的问题”。（见 paradigm-four）
5. 区块由清单上哪个组件承担？只引用，不增删。
6. 六种账号状态和四个极端下这页什么样？先想骨架、空、错、禁用。（见 reverse-check）
7. 一页只用一种主布局，同类页面同一种。范式平庸或不合适，走创新判断并留偏离说明。（见 when-to-innovate）
按序做page_pattern.py show → 规则卡 interface-pattern → 规则卡 interface-layout → 02-visual/page-blueprints.md
产出1. 02-visual/page-blueprints.md：每页：第一件事、三档信息、区块表、选择理由
检查1. 每个区块有“回答的问题”，每页一个视觉重心
2. page_pattern.py check 零违反，页面数与 BRIEF 一致
3. 证据薄的页面标“待样板页验证”
可偏离处1. 范式的 default 规则可偏离（写偏离说明），推荐组合只是起点；证据薄的页面按推演做，标待样板页验证

P4 视觉方向与令牌

目的从性格词走到可检查的令牌；用户确认方向后才开始画。
思考链1. 三个性格形容词、三条反目标、一个参照比喻；每个形容词对应一个看得见的选择。
2. 五个旋钮（暖冷、沉静活跃、随性庄重、疏密、纯平质感）各打 0–10 分，为什么？
3. 选 2–3 块风格板，各写为什么选、风险、作用范围；材质风格只作用于入口图标、指标图形、空状态、装饰。
4. 主色从哪来？行业气质、品牌色和官方色阶吻合吗？不合规的列“待裁定”，由用户决定。
5. 字阶、圆角、阴影、间距各取哪一套？深色是单独推导的还是取反？
6. 候选和资产范围给用户看；批准前不生图、不改页面代码、不发布。
按序做style_match.py → make_style_lab.py → audit_theme_discipline.py → export_tokens.py → design-craft.md
产出1. 02-visual/style-match.json：证据、决策、候选、approval
2. <名>.tokens.json：浅深两套令牌
检查1. 令牌文件检查通过（含深色），配色纪律无 FAIL
2. approval 为 approved 才生成素材
3. 三个性格词各指得出一处可见选择
可偏离处1. 用户给定品牌色：主色以品牌为准，色阶按规则推导，不合规处列待裁定
2. 超出现行规则的取值列待裁定，不悄悄放宽

P5 组件库与模块映射

目的选定组件库，把清单每个组件映射到库的真实组件，划清自定义块的边界。
思考链1. 这一端有哪些候选库？按端（后台、手机网页、小程序）查登记表。
2. 凭什么选？开发已定的技术栈、气质、暗色机制、主题接入方式；不凭喜好。
3. 清单每个组件对应库里哪个组件？列：清单项、库组件、主题接入、缺口。
4. 有缺口：能用库的原子组装吗？能就是自定义业务块；不能就问系统技能能否换成库里有的组件。
5. 自定义块只管布局、令牌与业务组合；按钮、输入框、表格、对话框一律用库的。
6. 库的暗色怎么接令牌？浅深两套各自过了对比度检查吗？
按序做component-libraries.json → 规则卡 interface-components → audit_rendered.py
产出1. 02-visual/component-map.md：库、主题接入、映射表、自定义块理由
检查1. 映射表条数等于清单的组件数
2. 每个自定义块写明库里没有、用哪些原子组装
3. 审计：该库组件至少 6 种，零手写控件
可偏离处1. 项目已有库：沿用，除非暗色或可访问性做不到
2. 智能体无专属登记项：按承载形态选网站或后台的库，写依据

P6 细节系统

目的图标、背景、卡片、配图各成一套有规则的系统，不逐个元素凑；数值见视觉设计规范相应各节。
思考链1. 图标：哪些对象要图标（系统技能定）？一物一图标。控件图标 2 像素线性，入口图标走已批准风格；颜色与饱和度上限见界面细节规范“二、图标”，生成的图标用 check_icon_image.py 验收。
2. 背景：页面底、分组底、卡片底、浮层底怎么分层？只靠留白、细线、浅底，不生成背景纹理；分层取值见界面细节规范“三、背景”。
3. 卡片家族：有几种卡片？各自谁是主角、整卡点去哪、一卡一个主按钮？九个家族与各自的字段顺序见界面细节规范“四、卡片家族”。
4. 配图：哪些对象要图（系统技能定）？来源顺序实拍、同风格摄影、同风格插画、矢量占位；缺图怎么降级？占位图不交付。
5. 记忆点落在哪一处？只许落在卡片造型、图形语言、插画或动效上。（见 signature-budget）
6. 自检：同组图同光同底同比例，卡片圆角不超过 4 种。
按序做规则卡 interface-details → check_icon_image.py → 规则卡 interface-icons → 规则卡 interface-components → 规则卡 interface-recipes → 规则卡 image-assets → cut_element_sheet.py
产出1. 02-visual/detail-system.md：图标表、背景分层、卡片家族、配图清单
检查1. 图标一物一图、一图一物
2. 卡片圆角不超过 4 种，阴影档在令牌内
3. 配图有来源与权利，无占位图；风格批准才调 Imagegen
可偏离处1. 入口图标可在已批准风格范围内选型；后台无需配图，卡片家族成员数随产品

P7 动效与状态

目的给变化定语法：哪些变化有动效、取哪个令牌、怎么降级；每页每种状态都有画面。
思考链1. 哪些变化需要说明“从哪来到哪去”（进入、展开、切换、加入购物车）？其余不动。
2. 每个动效取哪个配方与令牌？不在令牌里的时长和缓动不用。
3. 变化会让周围内容跳位吗？先预留空间，再动。
4. 减少动态效果时保留什么？位移改淡入或直接切换。
5. 每页的加载（骨架同形）、空（图加一句话加下一步）、错（原因加怎么办）、成功、禁用（写原因）都画了吗？写成页面乘状态的矩阵。
6. 时限（提示几秒消失、撤销几秒）归系统技能，这里只定形态不改时限。
按序做规则卡 interface-motion → motion-recipes.md → audit_stability.py
产出1. 02-visual/motion-and-states.md：动效清单与页面乘状态矩阵
检查1. 每个动效有减少动态效果的降级
2. 状态矩阵无空格，同页加载动画不超过 1 个
3. 稳定显示审计零报告
可偏离处1. 营销与品牌页可多用动效（仍在令牌内、可打断），后台默认几乎无动效

P8 原型与验证

目的用真实组件做成能点的页面，在真实浏览器里审、评分、改最低项。
思考链1. 页面、入口、动作、状态与系统技能清单逐项对得上，数字等于 BRIEF 里记的吗？每个控件是库的真实组件、颜色只来自主题吗？
2. 浅色深色、390 与桌面四张图，第一眼看到什么？等于第一落点吗？（见 three-second）
3. 评审十项各几分？最低项出在方案还是实现？在方案就回 P3 或 P4，不在实现里打补丁。
4. 反向检验过了吗：六种账号状态，加首次使用、弱网、超长文案、一件商品也没有。
5. 只改最低项，复评，直到没有 0 分且总分不低于 20（满分 30）。
6. 脚本全过只是必要条件，人眼也要过。
按序做规则卡 prototype-reference → build_prototype.py → audit_rendered.py → audit_palette.py → audit_stability.py → page_pattern.py check-page → design-craft.md
产出1. 原型页：项目模式为 03-小程序原型、04-后台原型
2. 02-visual/critique.md：四张图评分、提示条数前后
检查1. audit_rendered 浅色深色各零 ERROR
2. audit_palette、audit_stability、check-page 零报告
3. 评审无 0 项且总分不低于 20/30
4. 页面、入口、标签栏、组件数与 BRIEF 一致
可偏离处1. teardown 提示是建议，保留的写原因；后台评审里一致性高于创意

P9 交接与沉淀

目的把设计变成开发能照做的东西，把这次学到的留下来。
思考链1. 开发要的每个值都出自令牌文件吗？有只存在于口头或截图里的约定吗？
2. 页面、组件、动作有稳定编号并绑定到令牌与资产吗？
3. 偏离说明汇总了吗：每条能追到规则 id、理由、风险、验证结果？
4. 还剩哪些待裁定、待样板页验证？列给用户。
5. 这次有哪些新偏好、规则纠正、有效或失败的做法、来源与范围？写成一般原则；已有 key 就确认，不叠加。
6. 检查表每行都勾了、有产出了吗？
按序做export_tokens.py → design_path.py checklist → design_path.py deviation → experience.py note → validate_session.py → project.py link
产出1. <名>.tokens.json：开发只取这里的值，另附资产清单
2. BRIEF.md：采用的规则、偏离说明汇总、待裁定、本次沉淀
检查1. 经验库检查通过
2. BRIEF 的“采用的规则”“本次沉淀”齐全
3. 偏离说明四项齐全，令牌文件含深色并通过检查
可偏离处1. 小任务可把资产清单并入 BRIEF 的表

三、思考工具

工具怎么用
positioning
一句话定位
何时：P0 动手之前		1. 写成一句：给〔谁〕在〔场景〕〔完成什么〕，比同类〔多或少〕〔一点什么〕；“谁”带上设备与姿势
2. 之后每个决定回头对它，对不上的删
first-landing
第一件事与第一落点
何时：P0 写，P3 每页写，P8 验		1. 写出用户回到这一页做的第一件事，只许一件
2. 分别写新用户、回访、空数据下它是什么
3. 第一落点就是首屏第一个模块要回答的那个问题，其余模块只许辅助它
例：点单小程序：有进行中订单是取餐码，常客是再来一杯，新用户是选门店后看招牌品。
entry-ownership
入口归属三问
何时：P2 对入口表每一行		1. 哪一类（上下文、搜索、任务、状态、账户、订单、营销、内容、工具）、多高频
2. 有家了吗（标签栏、我的、顶部、页内）？有家不放第二个载体，没家按类型落默认区域
3. 表本身有错就退回系统技能
例：优惠券：账户类、中频，家在我的，首页不设入口，至多一条“有券将到期”的状态摘要。
five-questions
精简五问
何时：P2、P3 对每个模块，P8 复核；全文 page_pattern.py show method		1. 删除测试：删掉它，用户在首屏的决策会受影响吗
2. 类型：它的功能类型允许出现在这里吗
3. 去重：它的目的地在本页或标签栏出现过吗
4. 频次：它是并列、高频、核心的吗，还是为了凑满
5. 状态：这个用户状态下它是第一时间要做的事吗，能不能由状态决定显隐
paradigm-four
范式选择四问
何时：P3 每个区块选范式之前		1. 内容同质吗：同质用网格或列表，异质用模块或拼块
2. 浏览还是执行：浏览偏信息流与网格，执行偏入口大卡、列表、步骤
3. 数量与信息量：并列入口不足 5 个用入口大卡，5 个以上才考虑金刚栅格；每项文字多用列表
4. 有没有图：图主导用双列，没图用列表；答完再读候选范式的“选它前要问的问题”
例：点单页商品：同质、浏览加执行、60 款、有图，选左分类右双列卡片，不选瀑布流，等高利于比较。
density-test
密度检验
何时：P3 写蓝图，P8 复核		1. 首屏每块写一行“块、它回答的用户问题”；两块答同一问就合并，答不出就删
2. 首屏不超过 4 块，视觉重点不超过 3 个
3. 删光再一块块加回，每加一块说得出它挡住了谁；空着比凑数好
deletion-test
删除测试
何时：任何元素，从 P3 到 P8		1. 指着元素问：删掉它，用户的决策或理解会变吗？不会就删；会，再问能不能并入别的元素
2. 装饰也要过：它传达品牌或帮助分组了吗？没有就删
three-second
三秒测试
何时：P8 看四张截图		1. 截 390 宽首屏，浅色深色各一张，再模糊 8 像素看
2. 给没看过的人看三秒，问“这页让你做什么、第一眼看到什么”
3. 答案要等于 P0 写的第一落点；不等就是层级问题，先调大小、位置、留白，再考虑颜色
conflict-order
冲突裁决顺序
何时：两个都合理的做法互相冲突时		1. 写出两个做法各保护什么，按功能、无障碍与稳定、一致、清晰与密度、美观、个性找出各自所在的层
2. 保护更靠前一层的胜出；同层选改动更小的
3. 落败的记成偏离或待裁定，不悄悄丢掉
例：品牌想把按钮字做成浅金（个性），对比度只有 3:1（无障碍）：无障碍胜出，字用深色，品牌金只用在图形上。
deviation-note
偏离说明三行
何时：任一 default 规则不照做时		1. 标题写规则 id 与强度；must 不偏离，只能退回或换做法
2. 写三行：为什么偏离（业务依据，不是“更好看”）、风险（谁吃亏）、怎么验证（页面、状态或命令）
3. 写进 BRIEF 与 spec.json 的 deviations，用 design_path.py deviation 生成
signature-budget
记忆点预算
何时：P4 定额度，P6、P7 落地，P8 验收		1. 每个项目 1–3 个，后台 0–1 个
2. 每个来自品牌或场景，写出来源，落在一处可见元素上（卡片造型、图形语言、插画、动效），不改信息结构
3. 触碰 default 规则的同时写偏离说明；不动 must 与七条底线；删了它页面仍成立
例：取餐卡的杯贴缺口造型：来自品牌杯贴和取餐场景，落在状态卡轮廓上。
reverse-check
反向检验
何时：P3 预演，P8 实测		1. 六种账号状态（新用户、未完成、已完成、空、过载、被阻塞）各看一遍首屏
2. 四个极端：首次使用（什么数据都没有）、弱网（骨架超过 3 秒）、超长文案（商品名 40 字）、一件商品也没有
3. 每页每个状态问：第一个可操作模块是什么？会撑破、跳动、空洞吗？写成页面乘状态的矩阵，问题回 P3 或 P7 修
when-to-innovate
创新判断
何时：觉得范式平庸或不合适时（P3 到 P7）		1. 范式能回答这页的用户问题吗？能就用，不为不同而不同
2. 不能或太平庸：说清缺口（哪个问题没答好，哪个品牌特征不见了）
3. 只动可变量（构图比例、卡片造型、图形语言、动效节奏、文案排布、获批范围内的插画风格），不动 must 与七条底线；占记忆点预算，写偏离说明，样板页验证不过就退回默认做法
例：普通状态卡已够回答“好了没”；加杯贴缺口是为让品牌被记住，不是回答新问题，所以占一个记忆点。

四、常见失误

阶段症状原因怎么修
P0后期反复返工颜色与文案软偏好当了硬约束约束清单分两栏，硬的标来源
P1页面像某个同行的翻版把灵感图当证据，借了成品真实产品为主证据，只借属性
P2首页是 plan 输出原样把推演稿当了最终稿每个模块再过精简五问与密度检验
P2被拒入口查无下落拒绝时没记去处每个被拒功能写去处与规则 id
P3页面像模板套了推荐组合，没答四问逐个补答“选它前要问的问题”，写一行理由
P3满屏等大卡片没分主次先定主角，次要信息降一档
P4整页毛玻璃或黏土感材质风格当了全局风格只作用于批准范围，控件仍是线性矢量
P4深色像反相照浅色取反单独推导深色映射，再跑对比度
P5按钮、表单是手写的只引了库的样式表先列库的组件再排页面，用 --library 审计
P6图标块每张卡一个色相想靠颜色区分颜色只取主题与共用状态色，靠图形区分
P7内容一出来页面就跳骨架与真实内容不同形骨架按真实行数和图比例画
P8越改越乱一次改了所有低分项只改最低项，改完复评
P9BRIEF 到最后才补没有边做边记每阶段结束就勾检查表

五、方法依据

条目性质备注
十阶段顺序与各阶段产出技能内部规则串联现有流程与页面范式库，无新增外部主张
规则强度三档、偏离说明、精简五问技能内部规则沿用页面范式库的 method
冲突裁决顺序、七条底线、记忆点预算 1–3 个与后台 0–1 个技能内部规则顺序与数量是本技能取值，没有外部来源，靠样板项目验证
首页是路由决策：识别用户状态、突出最有用的动作、第一个模块答回来要做的事、六种账号状态评审通行做法一篇商业图库网站的编辑性文章（实例证据，海外应用）；原则采用，数值不采
标签栏 3–5 项、同一动作不放多处、不同导航模式各有用途通行做法两篇移动导航文章的窄依据，无研究出处
删除测试、眯眼测试、三秒测试、四个极端的反向检验通行做法通行评审做法，无逐条来源
设计决策的取舍方法、创新与约束的关系、评审方法的研究依据待外部资料核对外部资料检索未回来，待核对后补来源，期间不引用外部论述

平台矩阵

阶段小程序后台网站智能体
P0 接收与判定读胶囊与安全区；Skyline 或 WebView 决定瀑布流、粘性头能否用———
P2 入口与信息架构核对—不用首页范式，改用页面布局模式（规则卡 interface-pattern）；入口来自侧栏分组不用首页范式；按叙事排区块（价值、证据、行动）入口通常很少（会话、历史、设置），由系统技能定；不用首页范式
P3 页面清单与范式选择每页一个主任务；首页走六种账号状态；底栏处理安全区扫读效率第一，默认显示最需处理的子集，同类页同一布局一屏一个重点，每屏至多一个主动作回答、结果卡片、输入区居中版心，手机留边至少 16 像素
P4 视觉方向与令牌—一致性高于个性；状态用小圆点加文字品牌表达空间最大，记忆点可到 3 个—
P5 组件库与模块映射tdesign-miniprogram、vant-weapp、weui；网页原型用 vantelement-plus、ant-design、tdesign、arco-design、semi-design、naive-ui同后台的库；手机网页用 vant登记表无智能体专属项：按承载形态选网站或后台的库，写依据
P6 细节系统——配图权重最大，实拍优先，同光同调同比例—
P7 动效与状态———思考中、步骤展开、流式输出是状态重点，步骤文字状态随进展更新
P8 原型与验证390 宽审；新样式特性无官方兼容表，真机实测1440 与 390 都审；表格对齐与密度1440、768、390 三档；check_document.py --allow website超长回答、流式中断、空会话必走

案例样本

连锁茶饮点单小程序：22 家门店，到店自取为主；会员积分与储值；每月一档新品，常年第二杯半价；用户多为通勤的年轻上班族。系统技能交来标签栏 4 项（首页、点单、订单、我的）、19 条入口、8 页、31 个组件。以下数字与取舍是演示用的假设，不是真实采集。

阶段与问怎么答，得出什么偏离范式处
P0
谁、在哪、第一件事是什么？		单手、在路上；回访先取餐或再点常点的一杯。性格词清爽、利落、有份量，反目标促销味、塑料感、塞满；品牌绿与胶囊预留是硬约束。—
P1
同行首屏放几块、点单入口什么样？		（假设）拆 4 个同类应用：首屏 3–4 块，点单是整块大卡，会员码在我的。借大卡占首屏约三分之一；拒绝渐变按钮与开屏弹窗。—
P2
19 条入口各有几个家？		门店与取餐方式进顶部（全局上下文，各页沿用），搜索进顶部；点单、订单、我的是标签，首页不重复；进行中订单只出状态卡；再来一单、团餐、礼品卡 3 个并列任务，不足 5 个，用入口大卡，不为凑满金刚栅格补低频入口；新品与第二杯半价合成一个营销位；会员码、券、积分、储值只在我的（账户类只有一个家；点单已绑账号自动积分，到店只用取餐码，首页不需要会员码）。check 零违反。—
P3
首页第一个模块答什么？点单页用什么范式？		首页：取餐状态卡（有订单时）、再来一单主卡加两张小卡、营销轮播 2 帧。点单页四问：同质、浏览加执行、60 款、有图，选左分类右双列卡片，右栏等高自己处理。首发周把营销轮播提到再来一单之前，偏离 first-module-answers-return-task。为什么：首发周回访多为尝新。风险：常客多滑一屏，有订单的人看不到取餐码。验证：取餐卡仍固定第一，后台开关只在首发周开，“有订单”“常客”两种账号状态各截 390 图，首页到加购不超过 2 次点击。
P4
气质靠什么落地？		清爽对应低饱和、大留白；利落对应两档圆角；份量对应取餐卡用品牌色实心。风格板 fresh-organic，暖色促销板只用在营销位；主题取 milk-tea 作底，主色以客户品牌绿为准，不合规处列待裁定。—
P5
选哪个库？清单怎么映射？		小程序，选 tdesign-miniprogram，暗色机制与令牌接入对得上；31 个组件逐一映射，唯一缺口是取餐卡，用库的卡片与分割线原子组成自定义业务块。—
P6
图标、卡片、配图各是一套吗？		控件图标 2 像素线性；卡片家族 4 种（商品、入口、取餐、券）共用一档圆角与第 1 级阴影；商品以实拍为主，缺图用统一俯拍杯子插画。记忆点一：取餐卡的杯贴缺口。—
P7
哪些变化要动？		只给两处动：加购时杯子落入购物栏、取餐卡状态翻新；减少动态效果时改为角标淡入。记忆点二：杯口圆环作加载与空状态的统一图形。—
P8
第一眼看到什么？最低项是哪个？		390 浅深四张图，第一眼是取餐码或再来一杯，等于第一落点；评审 23/30，最低项“状态”1 分（空购物车没有下一步），只改它，复评 25；审计零报告。—
P9
开发拿什么？留下什么？		令牌文件、资产清单、1 条偏离说明；待裁定 1 项（品牌绿作浅色文字对比度不足）。沉淀一条有效做法（杯贴缺口取餐卡）、一条教训（首发周状态卡仍高于营销）。—

输出契约

  • 工作文件放会话的 raw 目录下：BRIEF.md、01-research/、02-visual/（page-pattern/、page-blueprints.md、component-map.md、detail-system.md、motion-and-states.md、critique.md、prompts/、style-match.json、visual-board.html），各阶段文件见产出一行。
  • BRIEF 放检查表：py -X utf8 scripts/design_path.py checklist --surface <端> --format md，每阶段一行写产出、检查结果、偏离说明，末尾写“本次沉淀”。偏离说明用 design_path.py deviation <规则 id> --why … --risk … --verify … 生成；首页的同一条也写进 spec.json 的 deviations（rule、why、risk、verify）。

质量门禁

  • 退回修改：增删系统技能已批准的页面、入口、标签栏项数、组件或按钮动作；违反七条底线；偏离 must 规则；default 被偏离却没有偏离说明或缺项；风格方向未确认就生成素材、改代码或发布。
  • 不得交付：评审有 0 分项或总分低于 20/30；浅色深色没各审一遍；没走六种账号状态和四个极端；检查表有未勾阶段；BRIEF 缺“采用的规则”“本次沉淀”。
  • 证据薄的取舍（资料未覆盖、置信度低）按推演做，标“待样板页验证”。

命令：py -X utf8 scripts/test_design_path.py；py -X utf8 scripts/check_document.py references/design-path.html；各阶段命令见检查表。

交接规则

  • 交给开发技能：令牌文件、资产清单（图标、配图、来源与权利）、动效令牌与场景表、页面组件动作的稳定编号、偏离说明汇总、待裁定清单；开发的值只取令牌文件。
  • 交回系统技能：退回清单（排不下、入口表有疑问、标签栏越界），项目模式走变更台账。
  • 结束前用 experience.py note 沉淀新偏好、规则纠正、有效或失败的做法、调研来源与范围，列入 BRIEF 的“本次沉淀”。
