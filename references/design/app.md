# App

应用状态按[成品要求](hard-rules.md)核对：全局纯白、界面禁绿与青绿、图形头像、独立业务页面及就近反馈。

触控优先的移动界面。按 [成品要求](hard-rules.md) 验证页面、流程与状态。设计建议与令牌见 [视觉基础](foundation.md)，页面结构见 [页面模式](patterns.md)。

## 先定平台

确认是原生、跨平台，还是移动 Web 或小程序，遵循目标平台的导航与系统行为。HTML 手机预览只是预览外壳，浏览器验证不等于原生验收；原生另测系统返回、手势、旋转、权限与真机，没有设备就写清边界。

## 起步

| 起点 | 用在 | 做法 |
|---|---|---|
| HTML 模板 | 定构图、取组件、做原型 | 打开 `templates/app/app.html` 预览（tab：整页模板、组件库），复制 `source/pages/` 的页面和 `kit/`；按编号取组件 |
| 可运行工程 | 要交付运行页面 | `py -X utf8 scripts/frontend.py init app-task`（Vue 与 Vant）；已有工程沿用其框架，用 `init existing` 纳入同一套检查 |

App 模板有五个完整页面：首页、列表（分类）、订单、我的、智能体（助手），另有“组件库”tab：按钮、背景、卡片、入口、导航、表单、列表行、数据、反馈、智能体、动效十一类共二百余个编号组件，每个有“适合”说明。组件按编号取用，见 [组件](components.md)。

## 结构要点

- **阅读路径。** 顶层导航放稳定目的地，页内筛选与详情分层；不把全部能力塞进首页图标矩阵。高频动作容易触及，固定底部操作栏预留安全区与键盘空间。
- **顶部。** 页首先按[视觉基础](foundation.md#间距圆角与层级)留出空间。需要定位时让简短标题和有用概览独立排布。搜索、对象、数据和关键操作从其下方紧凑展开。详情与填写页保留返回和对象名称。
- **底栏。** 常见起点为 3 至 5 项，上图下字，12 px 标签配 18–20 px 的黑色透明底图标。整项样式标记当前页，内容区为固定导航和安全区预留空间。
- **模块与列表。** 独立内容可用卡片分区。紧凑列表让对象、关键字段、状态与动作稳定对齐。
- **入口与操作。** 已有金刚标保留素材、尺寸、配色和样式。「我的」快捷入口优先上图下字，图形略大于标签，同组采用统一色。普通功能图标外框从 24 px 以内起步，整格保留触控面积。标题前图标同排等大。完整填写进独立页面，单字段原位改。
- **数据。** 图表放在对应卡片里，保留数值与单位，点选后在同区显示明细；触屏不把悬停当唯一通路。
- **局部切换。** 在页内把账号、时间或类别切换放在对应数据区顶部。阅读和触控顺序一致，切换只刷新下方同一组内容。可参考 `WB-LAYT-033` 的账号布局。
- **状态。** 加载用骨架，空态给对象与动作，避免整页闪换。

## 字体与间距

App 的标题、正文、说明和设置入口默认采用无单位的 `line-height: 1.5`。同一段文字换行时沿用这个行高。下面的距离从文字行框或卡片边缘量起，「一个字」取相应字号。

| 位置 | 建议取值 | 以 16 px 正文为例 |
|---|---|---|
| 标题、正文、说明等相邻文字块之间 | 取相邻两块中较小的字号。先计算各自的行高，再留一份块间距 | 18 px 标题到 16 px 正文留 16 px。16 px 正文到 14 px 说明留 14 px |
| 卡片上下内距 | 普通卡片上下各留正文基准字号的 0.5 倍 | 各 8 px |
| 同组相邻独立卡片 | 共用正文基准字号，沿排列方向留 0.5 倍 | 8 px |
| 图标和相配的文字 | 取标签字号的 0.5 倍，用于同行或上图下字的间距。既有金刚区沿用其版式 | 16 px 标签配 8 px，12 px 标签配 6 px |
| 设置卡里的每个入口 | 按入口主文字的字号，上下各留 0.75 倍。相邻文字行框之间合计约 1.5 倍 | 各 12 px，加 24 px 文字行高后，单行入口约 48 px |

整张卡由多条设置入口组成时，由各入口的内距承担上下留白，相邻入口保持连续，可用细线分组。多行名称或较高的行内控件可自然撑高入口。较小字号的入口仍以至少 44 CSS px 的触控高度为起点。取用 `AP-ROWS-001` 可看设置行，「我的」样板可核对卡片间距与偏好设置。实施时按实际中文、字号缩放与目标端复核。

## 移动端智能体输入栏

- 底部输入行从左到右为「加号、文本框、发送」。加号打开系统文件选择器，支持文件与图片；选中文件可在输入行上方预览文件名并移除。示例的上传入口和发送按钮采用至少 44 × 44 CSS px 的点击区。发送按钮按[文字比例](foundation.md#带文字的按钮)绘制，16 px 字的可见高度约 32 px。
- 文本框空白时一行高，录入换行和长句时向上自然增高，两侧按钮与底边对齐。达到视口可用高度的上限后框内滚动。删回短文本或发送后恢复一行，回车换行，中文组字和选词继续交给输入法。内容区给展开后的输入行和底部安全区留出空间。
- 建议问法放在会话区，停止与排队状态在需要时随对话显示。空消息禁用发送，文件与文字任一存在即可发送。可取用 `AP-CHAT-010` 组件或完整助手页。接入真实应用时按项目的文件服务处理上传与失败恢复。 [Web 文本框自适应尺寸](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/field-sizing)

## 手机浏览器中的稳定界面

- 移动 Web 和基于网页的应用按设备宽度布局，入口采用 `width=device-width, initial-scale=1`。铺到设备边缘时加 `viewport-fit=cover`，为顶部、底部和横屏两侧留出安全区。桌面预览的居中限宽属于样板外框，真机按可用宽度重新排布。
- 页面保持一个主要纵向滚动区。行、图片和表单按容器收缩或换行。确需二维浏览的表格、画布或地图使用有名称的局部滚动区。普通页面用自然高度，App 壳的最低高度可从 `100svh` 试起。需要追随浏览器工具栏的场景按目标端验证动态视口尺寸。键盘开合时结合实际可见区检查输入、提交和焦点。
- 手机可编辑输入的计算字号从 16 CSS px 起，保留用户主动缩放和字号设置。只对点按控件采用适用的手势设置，避免无意的双击放大。核对窄至 320 CSS px 的重排和放大文字后的可达性。展示机的专用固定外框在其项目范围内配置。
- 底栏贴边或与外框对齐，安全区只算入一次。为固定栏预留正文与聚焦位置，完整填写时让当前内容和提交先占可见空间。地址栏、横竖屏和键盘变化后保留当前输入和业务位置。

## 交付与验证

简报写清平台、主任务、目标设备宽高、导航归属、数据来源与要验证的状态。交付可运行页面与源码、素材与组件来源、目标宽度截图和操作记录。

在 320、390、430 CSS px 的代表宽度及实际目标端核对首屏、横屏、键盘和末尾。检查长中文、放大文字、错误、返回与焦点，逐个操作首项、中间项和末项。UX、AX、DX 的证据分别记录，见 [审阅](review.md)。
