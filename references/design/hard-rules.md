# 成品要求

当前任务明确指定的条件优先。App 与 Web 须执行下列前端背景、头像与图标要求。字号、间距、密度和排布等设计建议可按内容和平台调整。海报、演示文稿与其他文件使用各自的设计规则。本文是应用界面硬规则的唯一规范，历史色卡、品牌示例、组件说明和行业主题均按本文筛选。

| 范围 | 核对内容 |
|---|---|
| 各类成品 | 保留真实正文、必要事实、业务状态、来源与授权署名。生成内容和外部素材可追溯。 |
| App 与 Web | 用真实页面与状态核对业务动作、范围、反馈和恢复。按实际平台验证可读性、焦点、可访问名称、安全区和触控行为。外观从 [视觉基础](foundation.md) 起步。 |
| 海报 | 保留活动与商品事实。二维码、尺寸、印刷与发布规格按实际用途核验。构图从 [海报设计](poster.md) 起步。 |
| PPT | 保持文字和内容结构可编辑，核对来源、模板授权和最终放映。版式从 [演示设计](slides.md) 起步。 |

## 文字

- 任务所需的字段、名称、专名、术语和正文按事实保留。界面文案通常用简洁中文，品牌、双语或专业原文按实际内容保留。模板自带的示例事实须换成实际资料，过程证据和验证限制放在交付记录。
- 详情和独立办理页用一个简短标题定位当前对象或动作。标签落地页按下方[界面导航](#界面导航)直接呈现业务内容。保留必要的状态、错误与操作提示。

## 前端背景、头像与图标

- **页面底色固定为纯白 `#FFFFFF`。** App、Web 和小程序的页面画布、主内容区、全局页头与导航均呈现白色。透明布局层应透出白底。主题切换、背景图、伪元素或全屏渐变也不能给这些区域铺色。
- **应用界面禁用绿色和青绿色。** 文字、图标、按钮、标签、卡片、边线、阴影、渐变各色标、焦点、成功状态和图表系列均适用。可使用蓝、紫、橙、红、金、灰等可辨认色系。商品实拍、人物内容照片及自然景物保留原色。图片中的界面、功能图标或状态标识仍遵守界面配色。颜色收在组件边界内，默认、悬停、按下、选中、聚焦、禁用和错误状态都应可辨认。[Pastel 300](foundation.md#pastel-300-强调色) 和[花瓣色卡](huaban-palettes.html)仅作为搭配参考。
- **头像必须是图形图标。** 账户、成员和会话头像使用可辨认的图形图标，例如人物轮廓、角色或账户专属图形，缺省、未登录、资源加载失败时也显示本地图形图标。姓名放在头像旁。人物照片、姓名首字、拼音或英文缩写均不可充当头像。
- **功能图标采用简约、易辨认的线性图形。** 同一组保持图形线宽、端点和视觉大小协调，可按业务含义选用不同色系。
- **禁止任何文字形式的图标。** 使用真正的图形资源，例如 SVG 路径图标或透明底的位图图标。禁止用汉字、字母、数字、标点、Unicode 符号、Emoji、字体图标或含文字的 SVG、图片充当图标。普通按钮文案、图标旁的标签、业务数字与无障碍名称照常保留。纯图标按钮须有可访问名称。

## 图像

- 核对素材及字体的授权、署名、来源和用途。生成素材保留提示词、原始返回、派生裁切、用途及哈希，并检查实际接入的成品。用 [图像与素材](../image-assets.md) 处理 Imagegen 素材。业务事实与标题使用可编辑文本。
- 已有金刚标保留可辨认的图形、尺寸和图文排布。复用时核对图形与实际底板的对比，将文字图标换为图形。
- 涉及对象身份的标识采用稳定标识映射。不同对象使用可区分资产，按不可变对象 ID 持久化。刷新、改名、排序和换页都保持映射。生成标识须避免被误认为客户官方商标。
- 对象标识池扩充时检查重复和近似轮廓，沿用审阅过的风格。池耗尽时普通业务对象可暂时省略识别图，头像位则显示本地备用图标。

## 界面导航

- 主导航按真实的任务和目的地设置。主导航负责切换目的地，页内分类和集合管理所属内容。明确筛选范围，保持当前项与可访问状态一致。
- **标签落地页的顶部禁止展示标签名称和功能介绍。** 适用于 App、小程序、Web 一级导航及各独立页签面板。页头、原生导航栏标题、眉题、副标题、横幅和首卡均不得复述标签、改名重述或介绍该标签的用途。顶部直接放实际搜索、筛选、主操作、业务状态或首组内容。点击「知识库」后从搜索资料、导入入口或文档列表开始，删掉「知识库」「知识库管理」和「在这里统一管理资料」及其空容器。标签名称由选中项提供，辅助技术通过区域名称识别当前位置。独立详情和填写页保留具体对象或动作名称。
- 页面按从上到下的阅读顺序排布。控制某块数据的账号、时间、分类或视图切换，放在该块所有受控内容正上方。标题和通用操作可在切换项之前；当前对象的资料、摘要、指标、图表和明细都在其后。同一对象的资料只展示一次，切换项本身可以显示当前对象名称。
- 切换时只更新该控件所辖数据，加载、空态和失败也显示在控件下方。旧对象与新对象的数据不得混排。桌面并列区块各自遵循这个顺序；窄屏重排和键盘顺序也应先到切换项，再到对应内容。
- 同一页面内，每个业务动作或目的地只有一个入口。页头、导航、卡片和数据面板一起检查。已有明确入口的动作由原入口承接。
- 每个一级业务区承接独立的任务。任务的必需选择、办理、错误恢复和结果均在该区可达。通过同区只读引用和跨角色状态接力复用业务数据；用户主动切换主导航时才能进入其他一级区。
- 提供底部固定导航时，为内容和安全区预留空间，确保末项、键盘和关键操作可达。导航的具体外观与图标位置见 [视觉基础](foundation.md#图标与图像)。
- 同级筛选提供横滑时，手势、点击和键盘切换保持一致。局部筛选只影响所属面板，输入、滚动、图表操作和正在编辑的表单不误切业务。隐藏内容不进入可操作和焦点顺序。
- 返回恢复上级列表的筛选、选中项、滚动和触发焦点。完成、恢复等操作可改变数据归属，避免未经用户主动选择切走主导航。
- 状态提供可辨认的文字、形状或其它非颜色线索。同组的确认、保存与取消靠近当前动作。新建入口的摆放和图标形式按所属模块和可辨识性决定。

## 界面卡片布局

- Web 同一布局里的纵向相邻卡片上下贴合，边界之间为 0 像素。App 的相邻独立卡片以半个正文字号为间距起点，设置行等共同构成一张卡的内容可用细线分隔。切换、展开或收起改变内容时，相邻卡片跟随重排。见 [App 字体与间距](app.md#字体与间距)。
- 同排卡片顶边、底边对齐；同一列沿统一的左右边线。响应式换列后重新核对。卡片内部按内容保留清楚的层级、内边距和点击范围。

## 界面数据表达

- 同一页面内，同一个指标或数据类型只展示一次。以指标定义和实际数据为准，合并页头、汇总卡、图表、分析文字和明细里换名复述的内容。同一指标的时间、分组或维度在它所属的一个组件内切换。图例、坐标轴、等价的无障碍说明和点选读数是图表的一部分。业务明细只放当前图表未表达且完成任务需要的独立字段。
- 时间序列用折线。累计数据有完整的来源构成时用饼图或环图，有明确目标时用进度。横向类别对比可用条形。独立的总数、汇总值及单点统计直接用文字数字和单位。按关系选图，成品布局见[数据看板](patterns.md#数据看板)。
- 饼图或环图仅表达同单位、非负、互斥且组成完整总体的项目；达成超过百分之百时直接显示真实达成值，不能用饼图强行截成完成。折线保留真实顺序和缺口，不为画出连续曲线把未知补零、插值或平滑改变走势。金额和数量分开选择，禁止混成一个综合百分比。
- 图表须有明确对象、系列、单位和所选范围；必要业务周次依照已确认例外显示。减弱网格和装饰，颜色与状态保持一致，系列用线型、点型或文字辅助区分。禁止三维饼图、无业务意义的仪表盘、随机趋势和假的增长数字。
- 指标明细每个指标占一行，指标名称与单位同排，例如“线索量 条”，窄屏按可读性重排。筛选周次后图表、数值和记录整体对应所选周；用户要求单周时不继续展示只平移一个点的多周趋势。只有周汇总就展示本周完整指标；没有每日原始数据不能制造七天折线，不同单位不能混成一条数值曲线。
- 鼠标悬浮、键盘焦点与触屏点选都可取得同等具体数值；触屏在图表同区域更新明细，无弹窗。Canvas 图形必须有可访问名称与对应 DOM 数据，不能只依赖像素图。无数据、部分数据、零目标和长金额分别检查，未知不显示零或满进度。

## 界面交互

- **业务详情、办理和导航禁止使用边缘抽屉、侧滑面板、底部弹层或居中业务弹窗。** 详情进入独立页面或紧邻原对象展开；窄屏导航使用正常文档布局、独立目的地或底部固定导航。
- **填写业务表单必须进入所属业务的独立页面。** 新增对象、补充业务记录、填写正文、由授权角色维护计划等进入独立页面或有独立路由的页面视图，禁止任何方向滑入面板、居中表单弹窗和屏幕外偷偷追加的表单。打开填写页时原列表不与表单上下堆叠。名称等单字段纠错继续原显示区域编辑，不扩大为填表页面。
- 填写页在当前业务范围内完成一整件事，自动带入账号、业务线、周次和已有合法值；保留返回入口，保存取消就近成组。取消、返回及保存后恢复原列表的筛选、对象、滚动与焦点，草稿恢复只能在用户再次主动进入填写时发生。不得因刷新、选中记录或切换标签自动进入编辑态。
- **通知和警告允许弹窗或轻提示。** 采用成熟组件，通知不窃取焦点、不挡主要动作；需要确认的警告使用居中、无方向滑动的对话框，支持键盘和焦点恢复，确认取消相邻。该例外不允许文本框、业务表单、填写步骤或嵌套弹窗；不能把填写表单命名为“通知”绕过规则。校验错误优先放在对应字段附近并保留输入，必要信息不可只靠短暂通知。下拉选项与纯信息悬浮提示按各自限定条款执行。
- 筛选选中条件清楚可见。可按宽度选择紧凑单行、换行或就近下拉。允许与触发框就近的下拉选项层；不得借此引入边缘滑出选择器。图表指标、客户进度、账号及业务分类等按真实宽度验证。
- 筛选控件默认只影响它下方的所属内容区。独立概览与下方列表要各有明确口径，同一指标和范围只呈现一次。共同控制概览和列表的范围切换放在两者上方，并标明作用范围。
- 数字及通用字段在用户进入表单后提供合理默认值：沿用当前账号、业务线、周次与已有合法值；新增增量可从零开始。次数、数量、金额和可切换的进度字段在原字段位置使用纵向滚轮，允许上下滑动并直接手输，不在数字下方添加横向滑块，不弹出边缘选择器。用户已确认的豁免：购物车行、加购条、列表行里的行内数量步进器（加减钮加数字，可直接输入，有上下限）可以保留，因为这里是就地改一件商品的件数；表单里的数量、次数、金额字段仍用滚轮。复用成熟选择器并隐藏其默认确认取消工具栏，统一由整张表单提交。当前值清楚可读；提供键盘和触屏路径；中文输入法不误提交。提交前停止滚动惯性并同步仍在编辑的输入，不能保存上一项。常用选项范围不是业务上限，超出快捷范围的合法值仍可输入；金额精度、数量整数与自定义进度按实际业务校验。默认值只属于未提交草稿，未知历史、未填写目标不能被默默补零，姓名和工作事实不能编造。

### 操作结果的位置

- 每个操作明确触发对象、作用范围、结果容器和返回位置。**结果必须紧邻被操作的对象，或进入独立详情页。** 禁止把所选卡片的详情、展开内容、表单或错误统一追加在整组列表末尾、页底或其它远处；“已经出现在文档中”不等于用户看得见。
- 就近展开时，内容是该卡片或行的直接内容，显示在其内部或紧邻下方，配对 `aria-expanded` 与 `aria-controls`；不是排在其它兄弟卡片之后。首项、中间项、末项和长列表都要验证，不能只点恰好在列表末尾的一项。
- 结果较长、窄屏难以看见或需要独立操作时用详情页。打开后标题与主要内容立即可见，焦点进入新页面；底下不继续堆原列表。返回时恢复来源筛选、对象、滚动位置和触发焦点；列表重新渲染也用稳定对象标识找到原入口。
- 桌面分栏仅在触发对象与详情同时位于当前视野、关系明确时可用。窄屏必须切换成就近展开或详情页，禁止将右栏直接排到长列表下方。不能用强制滚到底部、提示“请向下查看”或短暂通知弥补错误结构。
- 预览、版本切换、记录详情、附件、数据点、校验反馈同样适用。局部动作只更新所属区域；打开详情不等于打开编辑，返回不能自动展开其它对象。完整填写仍遵循独立填写页合同。

### 业务周期

- **填写记录使用具体年月日，不以周次或起止时间段代替。** 日期放在所属填写区域并可修改；当前新增按业务时区带入当前日，历史补录的默认值只是可核对的草稿，不冒称已发生事实。日期选择复用成熟组件，就近或内嵌展开，支持键盘输入，提交同步尚在滚动或编辑的值，不另设一套确认取消。
- 具体日期与周期汇总分开：新记录保存单日日期，服务端验证真实日历与允许范围，再计算其所属周或其它周期；不能只改显示文案却仍只存范围。汇总页仍可显示起止日期，填写页不重复显示时间段。原始资料只有周期汇总时保留该粒度，禁止把周一、周末、导入时间或创建时间填成历史业务日期；补录或更正由人选择日期并保留原记录。
- 用户要求按周期查看时，在选择器显示实际起止日期并给出完整可访问名称；周范围按业务时区与真实周历计算，跨月跨年也必须准确。这是明确授权的业务日期，禁止顺势添加装饰日期。
- 回顾和实绩查看最多选到当前周期；当前周期的前进按钮禁用。不能把导入表的最后一周当系统当前周；页面重新聚焦和提交时复核上界，前后端都拒绝越界。需要未来计划时仅由另行明确的业务权限与范围支持，不自行放开销售端。
- 所选周须刷新该周的全部指标、明细、目标和工作内容，不能沿用多周图仅换一个点；指标数据不足时保留真实缺口，不制造每日曲线。周期只对标明范围的内容生效，不能突破局部筛选的方向约束。

### 悬浮说明

- 文本框与可点击卡片用字重、短标记或图形区分点击、焦点与当前态。组件可沿用白底或采用项目配色。悬浮数据提示默认白底深字。分组分隔线属于布局层级。
- 无可见文字的功能图标必须在鼠标悬浮和键盘焦点时显示中文功能名。图表数据点提供具体对象、数值、单位及必要口径，不捏造数据；已有完整文字的按钮不重复附加无用提示。
- 提示锚定触发对象，不遮住对象，不改变页面布局。可按 Escape 关闭且不移动焦点；鼠标可移入提示阅读；只在离开触发区和提示区、主动关闭或内容失效后隐藏，不限时自动消失。
- 提示只做补充，必要业务内容、错误和决策依据不能仅藏在悬浮层。触屏通过可点选数据点的同区域明细或原有可见字段访问同等信息，不能要求悬停；图标仍有独立的可访问名称。
- 悬浮提示只放功能名与数据口径，不用来重新放入长段解释、建议、日期或设计自述；按周业务明确要求时允许必要的周次标识，其他无关日期仍禁止。

### 原位修改与业务闭环

- 修改必须发生在该业务所属页面。改名称等单字段操作，原显示区域直接切换为输入框，不新建编辑页面、不跳转、不滚动到别处、不替换顶部为遥远的编辑器。保存与取消在输入框旁或紧邻下方同排成组；阅读态不显示这些按钮，用户主动进入编辑后才显示。
- 阅读态与编辑态保持位置、对齐和内容宽度连续。保存成功原位更新，取消恢复原值；失败保留输入并在同区域反馈。失焦不得擅自提交或丢弃；中文输入法确认不能误触提交。筛选、所选对象和上下文保持，动作不得自动切标签。
- 进入录音、导入、纪要或详情页面**不等于进入填写状态**。默认只显示内容、选择入口和当前业务动作；只有用户明确点击“填写”“编辑纪要”等按钮后才展示文本框与保存取消。禁止以已选中一条记录为理由自动打开表单。切换记录、返回、保存或取消后恢复阅读态，实际逐条验证，不只扫描首页。
- 录音、导入资料及智能提取流程必须使用当前实际资料，保留原文、来源对象和失败状态；不能把模板预设流程或样例内容混入真实纪要、需求或生成结果。没有资料时保持空态，没有明确需求时不得凭空生成业务。资料更正后重新核对派生需求，不能悄悄使用过期结果。生成内容应能追溯到来源并在当前业务内预览和操作，失败保留原资料并可重试；是否接入真实服务须有实际验证，不用预置页面冒称生成完成。
- 基础资料纠错与业务增量分开：名称纠错可原位改；新增客户、洽谈、拜访、回款、周工作记录等必须追加独立记录，保留旧记录和归属。需要更正已提交业务记录时追加更正与关联依据，不能覆盖历史伪装成新增。
- 功能高内聚低耦合：一个当前业务入口能完成完整业务，既有客户、账号、部门、业务线、周次等上下文自动带入；不要求去多个标签、重复填写表单或修改多个位置才能完成一件事。无用途的按钮、搜索、步骤和统计都删掉。
- 新建对象进入所属业务的独立新增页，返回仍在左上并恢复列表；不能跳到其它主标签。计划、配额和目标按业务明确的角色维护；非维护角色只读，不在其页面重复放一个可填写的计划模块。执行角色的页面不保留独立计划编辑模块，维护入口仅由已授权角色使用。权限必须由服务端验证，不能只隐藏按钮。工作内容可由智能服务整理，必须基于该周真实记录，保留原文、出处和人工核对；服务未接入不得把关键词拼接冒称智能总结。
- 业务周期、金额单位与达成度口径必须来自用户资料或明确确认。不同周的计划和实绩不得相除；缺数据不当零，目标为零不产生无穷百分比，不随意平均数量与金额指标。

## 必须核对

在适用视口、输入方式与状态下验证真实内容、上一级恢复、输入与反馈、筛选范围、数据口径、权限、焦点、点击范围和素材加载。对容易辨认错的图标、窄屏长标题和重要事实结合截图复核。检查通过的证据绑定当前成品和要求。版式取舍单独记为设计观察。
