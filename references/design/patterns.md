# 页面模式

先定页面类型，再取对应模板改内容。五类页面在 `templates/app/` 和 `templates/web/` 各有一份可运行模板，另有组件库，换成自己业务的对象后保留结构。没有对应业务的页面直接不做，不凑数。

## 导航与入口

| 项 | App | Web |
|---|---|---|
| 主导航 | 底栏可从 3 至 5 项起步，上图下字，注意内容与底部安全区 | 左侧栏优先图标在左、文字在右，两者约等大，选中项清楚可辨 |
| 本库默认 | 首页、分类、订单、助手、我的 | 工作台、列表、订单、助手，底部“我的” |
| 页内切换 | 纯文字圆角分段，只改变下方内容 | 同左 |
| 返回 | 只在页面左上，恢复来源筛选、位置与焦点 | 同左 |

- 一个目的地只有一个入口。底栏或侧栏负责切换标签；当前标签里的按钮只服务当前业务，不重复也不跳往其它标签。
- 金刚区按批准的入口表组织同级业务。功能归属见 [System 入口规范](../../../Luz-System/references/ui-standards.html#entry-ownership)。
- 导航项少于 3 个用分段，多于 5 个收进“更多”或分组，不堆在底栏。页面顶部标题不与导航标签同字。

## 五类页面

| 页面 | App 结构 | Web 结构 | 必有状态 |
|---|---|---|---|
| 首页或工作台 | 平面顶部（定位、搜索、概览）、金刚入口、浅色模块卡、紧凑业务行 | 平面顶部、指标卡、趋势与占比图、最新记录表、待处理列表 | 加载骨架、无数据 |
| 列表 | 搜索、分段、单行筛选、紧凑行、就近展开、独立详情、加载更多 | 工具条、可排序表格、分页、勾选批量、右侧关联详情、独立填写页 | 骨架、筛选无结果、批量确认 |
| 订单 | 状态分段、订单卡、按状态给操作、详情时间线、独立售后填写页 | 状态分段、订单表、行内展开、详情页、状态变更确认 | 空分段、取消确认、提交校验 |
| 我的或账号 | 资料头部、数据面板、地址等模块、原位改名、独立新建页、偏好开关 | 资料概览、键值卡原位修改、偏好、设备表、独立修改密码页 | 校验错误、退出确认 |
| 智能体 | 会话流：思考过程、工具调用、流式回答、审批、任务、输入栏 | 三栏：会话历史、对话、过程与产物 | 生成中、失败重试、空会话、排队 |

页面里的块与组件库里的组件都有编号，用 `py -X utf8 scripts/template_registry.py list --kind app --page home` 查看，`show <编号>` 取出该组件的代码与所需样式；组件库见 [组件](components.md)。

## 选用与改造

1. 写下页面的主任务、主对象和必须保留的槽位，再对照上表选模板。
2. 把商品、订单、客户换成真实对象，字段按业务取舍；不保留模板里没有业务用途的按钮、搜索、步骤和统计。
3. 顶部先看有没有有用内容：定位、搜索、概览数据、图片都要有实际用途，没有就不放。
4. 模块沿同一栅格对齐，纵向相邻卡片上下相接。标题可放在卡片头左侧，用统一内边距和分隔线界定内容。
5. 一次业务尽量在所属位置闭环：详情就近展开或进入详情页，完整填写进独立页面，单字段原位改。交互合同见 [可复用交互合同](interaction-contract.md)。
6. 状态逐项覆盖：加载、空、错误、成功、无权限、长内容。没有依据的业绩、评价、人数不编造。

## 响应式

- App 以 360 至 430 宽设计；Web 在 1440、1200、900、760 宽检查，列数随断点减少，表格保留横向滚动，主从分栏在窄屏改为单页详情。
- 窄屏不是把桌面缩小：分栏变成列表到详情，次要筛选收进下拉，表格保留对象与操作。Web 页面缩到多窄仍按 Web 字号下限。

入口表契约（System 交付的 entrances.json）由 `scripts/page_pattern.py` 校验，规则页见 [页面范式库](../page-patterns.html)。
