# 页面模式

应用状态按[成品要求](hard-rules.md)核对：全局纯白、界面禁绿与青绿、图形头像、独立业务页面及就近反馈。

以 System 的页面、模块顺序、控件与第一视觉重心为输入。先排出一条能读懂的主路径，再为有业务依据的状态和内容增加视觉层次。以下五类页面是模板的检索入口，按真实任务取用其中的组件与呈现方式。

## 导航与入口

| 项 | App | Web |
|---|---|---|
| 主导航 | 已确认底栏时，让文字、选中标记与安全区清楚可见 | 按已定目的地呈现导航，名称与选中态清楚 |
| 页内切换 | 按功能区别目的地、内容面板与过滤条件，当前取值可见 | 呈现同样的业务含义，支持键盘操作 |
| 返回 | 返回后能接上原对象、筛选和位置 | 恢复来源区域与键盘焦点 |

- 一个功能在同一角色下有一个主入口。经批准的快捷入口沿用相同目的地、对象和权限。
- 功能归属、导航层级和数量按已确认的 [System 入口表](../../../Luz-System/references/ui-standards.html#entry-ownership)。在成品检查文字长度、触达与可见的选中态。

## 五类页面

| 页面 | App 可借用的呈现 | Web 可借用的呈现 | 对照业务检查 |
|---|---|---|---|
| 首页或工作台 | 让当前任务、对象与状态先可见 | 以共同对齐和留白突出第一项决定 | 初次使用、已有任务 |
| 列表 | 记录的关键字段对齐，相关操作靠近对象 | 按比较任务选表格或连续行，对象与操作相互对应 | 筛选无结果、权限差异 |
| 订单 | 清楚区分生效信息与待处理请求 | 详情按业务依赖排，需要核对的内容可并排 | 待确认、生效、冲突 |
| 我的或账号 | 个人资料和账户设置的可操作状态易辨认 | 展示值、编辑值与反馈靠近对应字段 | 校验错误、放弃修改 |
| 智能体 | 当前输入、正在处理的任务与可用结果容易区分 | 根据已确认的阅读或对照任务安排对话、记录或结果 | 生成中、可恢复失败 |

页面里的块与组件库里的组件都有编号，用 `py -X utf8 scripts/template_registry.py list --kind app --page home` 查看，`show <编号>` 取出该组件的代码与所需样式；组件库见 [组件](components.md)。

## 数据看板

先给每个指标写出名称、口径、维度、单位和期间，给每个目标动作写出目的地与对象。对照 [界面数据表达](hard-rules.md#界面数据表达)，从页头到页尾核对同一指标只有一个展示位置、同一动作只有一个入口。例如，销售额已经用一张趋势图承载，同页的销售额汇总、分析段和分类重复卡并入该区域或省略。

| 数据关系 | 样式建议 | 信息位置 |
|---|---|---|
| 按天、按周或实时变化 | 折线，可给主线加浅面积填充 | 横轴时间、纵轴单位。点选值随当前数据点更新 |
| 累计来源或分类构成 | 饼图或环图，各项合成同一个总体 | 标签、比例在同一组图例里排列。环心可以留白 |
| 累计完成情况 | 进度条或目标差值 | 同一区交代实际与目标，超额显示真实值 |
| 独立总量、计数或汇总比率 | 大字数值加单位和短标签 | 直接放在它自己的卡片或行 |

- 用纯白画布承载数据。普通卡片可留白，重点卡片可用项目自选的纯色或渐变，按实际底色与间距建立层次。主趋势用能与次要系列区分的强调色。分类清楚标注，同一系列整页沿用同色。网格、刻度、分隔线弱于数据线，浅面积填充只衬托对应的趋势。
- 按本页要回答的问题确定主图或数字的视觉分量。同层数据可并排对照，窄屏回到已定阅读顺序。单位靠近数字，同组沿共同边线组织，组内圆角按[视觉基础](foundation.md#间距圆角与层级)处理。
- 参考图只用于选择背景、卡面、字体层级、图表配色、栅格和间距。标题、内容、图标、品牌和数字使用项目本身的数据与素材。见 [Web 工作台样板](../../templates/web/source/pages/home.html)。

## 选用与改造

1. 写下页面的主任务、主对象和必须保留的槽位，再对照上表选模板。
2. 把样板对象、字段和操作替换为已确认的功能清单；模板里的示例按钮、搜索、步骤和统计只有在清单中有相应用途时才保留。
3. 顶部先看有没有有用内容：定位、搜索、概览数据、图片都要有实际用途，没有就不放。
4. 模块沿同一栅格对齐。Web 纵向同组卡片相接，App 独立卡片按[字阶与间距](app.md#字体与间距)留统一细缝。标题可放在卡片头左侧，用统一内边距界定内容。
5. 一次业务尽量在所属位置闭环：详情就近展开或进入详情页，完整填写进独立页面，单字段原位改。交互合同见 [可复用交互合同](interaction-contract.md)。
6. 状态逐项覆盖：加载、空、错误、成功、无权限、长内容。没有依据的业绩、评价、人数不编造。

## 响应式

- App 以 360 至 430 宽设计；Web 在 1440、1200、900、760 宽检查，列数随断点减少，表格保留横向滚动，主从分栏在窄屏改为单页详情。
- 窄屏不是把桌面缩小：分栏变成列表到详情，次要筛选收进下拉，表格保留对象与操作。Web 页面缩到多窄仍按 Web 字号下限。

入口表契约（System 交付的 entrances.json）由 `scripts/page_pattern.py` 校验，规则页见 [页面范式库](../page-patterns.html)。
