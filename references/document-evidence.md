# 有依据的文档创建与验收

适用：七个 Luz 技能产出的研究、系统、功能、逻辑、UI、技术、验收及运维文档，包括 HTML、PDF、Word、表格和演示稿。本文负责内容与成品的证据合同；调研数量、原文与模板绑定沿用 Crawl [evidence-policy.md](../../Luz-Crawl/references/evidence-policy.md)，版式沿用 [file-design.html](file-design.html)，不另立第二套门槛。

## 内容与引用

先有已读材料、用户确认和真实观察，再组织文档。模型可以归纳、改写和提出有依据的方案，不得独立编造事实或把方案推导冒充外部事实。记录复用已有 `plan.json`、项目 data、Writing 声明表和 Crawl findings，不要求重复维护五份台账。

| 内容性质 | 必须留下的依据 | 给读者的表达 |
|---|---|---|
| 外部事实 | 原发布方、原文定位、逐字摘录、版本/日期/地区、适用条件、采用位置 | 关键主张就近引用；文末列可查的原文 |
| 用户确认的规则 | 当前会话原话或客户材料位置、确认范围 | 写为本项目约束，不能由网上案例补出客户事实 |
| 本地观察 | 当前文件/构建、实际命令或操作、结果及未测范围 | 写清观察环境；离线夹具不代表产品验收 |
| 本次方案推导 | 目标、输入依据、备选、选择理由、代价、待验证条件 | 明说“本次选择/拟采用”，不能假称来源或客户已确认 |
| 未核实内容 | 具体缺口、影响、下一步证据 | 关键缺口阻塞依赖它的成稿；非关键限制保留，不能改写为肯定能力 |

正文的关键数字、规则、能力、限制、引文和技术决定可追溯到具体依据；引用须支持相邻主张，不能只在文末堆网址。引用保留条件、否定、范围与版本，来源冲突记录裁决理由。规范只有一个权威发布方时，不伪造第二个独立来源。

外部研究支持的正式文档默认保留可见参考。HTML 使用正文引用锚点和文末标题链接；PDF 使用可读的来源编号、发布方、标题、章节/页码及原文地址或 DOI，核对导出后的链接。易变事实注明核对日期与适用版本。作者、日期或版本未找到就标未提供，不能猜填。

“内容自足”表示读者不必打开另一份内部文件才能完成本文件任务，不等于禁止参考文献、法规名或来源网址。过程哈希、审批状态、工具日志、私有路径留在 raw；来源、实际限制和适用版本属于内容，不能为了页面简洁删掉。不得公开私人材料、凭据或受限文件地址。用户明确要求纯文案时按其格式交付，内部声明表仍保留依据；不能以此隐藏影响读者理解的关键不确定性。

## 执行与验收

1. **定义文档任务。** 写清读者要理解、决定或完成什么，列问题与章节，不按模板默认业务内容填空。教程、操作指南、参考规范和方案解释各自组织，必要时分节；重复事实只维护一处。
2. **调研并建立证据关系。** 按本阶段 Crawl 问题计划读正文、追一手、比较方案与反例；完成 question_id → finding → 具体输出的覆盖。只读小节须如实记阅读范围。没有依据的市场指标、成本、收益、客户痛点和能力不写成事实。
3. **先结构再表达。** 先列结论与适用范围，再展开依据、取舍、结构/流程、实施及验收。架构图画系统边界、职责和主要关系；流程图含状态、角色、异常与恢复。表格用于平行比较，叙述解释推理；不强制每节只有表格，也不把整篇挤进长单元格。
4. **选择真实模板并生成。** 读对应 Design 卡，list/select 绑定准确产出，再调用模板生成器。保存可编辑源，HTML/PDF 均从同一内容源生成，不手改派生成品。使用另一输出的选择记录或只拷模板外观不能通过。
5. **复核内容。** 逐项核对关键主张、引用支持、数字单位、术语、图表与正文、功能编号及跨文档的一致性；关键缺口、失效引用与未执行的测试不得标通过。
6. **检查真实成品。** HTML 在实际浏览器查看桌面和窄屏，检查标题层级、表格、长文字、引用跳转、键盘焦点及打印预览。PDF 重新打开并逐页渲染检查裁切、乱码、孤立标题、表头/续表、目录页码与书签目的地，核对文字层、字体、标题与阅读顺序；不能只检查源 DOCX 或文件存在。
7. **检查无障碍边界。** 标题使用语义样式，图有替代文字，表有表头，文档语言正确。PDF 用 `check_pdf.py`，要求无障碍交付时加 `--accessible`；结构标签存在不能证明阅读顺序正确，仍须按任务实际测试键盘/辅助技术。未做则写明未做，不宣称 PDF/UA 或 WCAG 全面符合。
8. **封存和反馈。** 真实生成器登记最终文件哈希，展示/交付前 post 检查；内容或源变化重新生成并复核受影响部分。将失败症状、修复、证据、适用范围及待复核条件写 note，BRIEF 记录采用规则与本次沉淀。

浏览器打印型 PDF 必须核对当前引擎的纸张、print/screen media、字体、链接、书签与标签选项；不能假定默认启用。客户正式文档仍走既有 Word 模板导出路径。导出成功只代表得到文件，不能替代上面的内容和逐页验收。

## UI 参考的证据范围

每种关键页面/交互从相关成熟产品或官方设计系统取得真实图像，并实际查看。记录 URL、版本/日期、截图位置与哈希、页面/状态/视口、具体观察、采用处和差异；有图文件但未查看不能写“已参考”。公开示例只证明它展示的内容，不代表完整业务系统已验证。

在授权范围内实际操作关键流程，记录前置条件、输入、动作、焦点/状态/数据变化、恢复与结果。仅有截图不能证明点击、权限、后端写入、取消、编辑返回和重复提交有效；静态 `#` 链接须标为占位。系统整体一致性按 Project 的功能链路与质量规则核对，不能靠单张好看的页面替代。

## 方法依据与边界

- Diátaxis [Reference](https://diataxis.fr/reference/)：参考资料的结构反映被描述系统，区别于操作与解释。本文的实际章节方案属于本地设计决定。
- W3C PDF 技术 [PDF3](https://www.w3.org/WAI/WCAG22/Techniques/pdf/PDF3)、[PDF9](https://www.w3.org/WAI/WCAG22/Techniques/pdf/PDF9)、[PDF2](https://www.w3.org/WAI/WCAG22/Techniques/pdf/PDF2)：阅读顺序、标题与书签。技术示例不等于完整合规认证。
- Playwright [page.pdf](https://playwright.dev/docs/api/class-page#page-pdf)：打印媒体、纸张与 tagged/outline 等导出选项；依据本轮实际读取的 PDF 小节，不声称读完全部 API。
- GOV.UK [Check answers](https://design-system.service.gov.uk/patterns/check-answers/) 和 [Error summary](https://design-system.service.gov.uk/components/error-summary/)：编辑返回与输入保留、错误摘要与字段关联。已查看官方示例图像，错误链接聚焦输入已操作；确认页的占位链接没有真实修改/提交证据。
