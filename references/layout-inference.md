# 自适应界面视觉匹配协议

这份协议把灵感案例变成可解释的设计决策。它不把某个案例的数量、列数、背景色或风格直接复制到产品页面。

## 1. 三层信息

每次界面视觉任务先把 brief 拆成三层，并在匹配结果中分开保存：

| 层 | 保存什么 | 处理方式 |
| --- | --- | --- |
| 证据层 | 参考案例的关键词、数量、排列、材质、色彩、动效和来源短语 | 作为候选评分和解释；例如“5×2”写入 `evidence.layout_hints` |
| 语义约束层 | 用户明确要求的内容关系、信息优先级、控件可读性和品牌边界 | 必须保留；例如“非对称指标看板”保留主指标锚点、辅助指标和独立信息面板三种关系 |
| 决策层 | 根据内容量、对象类型、优先级、交互强度、视口和可用宽度得到的区域、列数、比例、折叠顺序、图标角色和风格候选 | 可调整；用 `decisions` 和 `adaptation` 解释调整原因 |

数字排列、颜色和材质默认属于证据层。只有 brief 使用“必须、固定、严格使用、不可调整、锁定、强制”等明确语言时，才可升级为硬约束，并把原文写进 `layout.hard_constraints`。

## 2. 自适应布局推理

运行 `py -X utf8 scripts/style_match.py --brief "..." --input <json> --output <match.json>`。输入可以补充：

- `viewport.width`、`viewport.height`：用于计算可用宽度、断点和内容折叠顺序。
- `content.items` 或具体对象数量：用于计算卡片最小宽度和列数；`content.longest_label`：入口最长文案的字数，用于金刚区。
- `content.primary_metrics`、`supporting_metrics`、`panel_items`：用于指标看板的区域权重。
- `content.images`：用于图文页的图片区列数和裁切策略。

匹配器先确定页面意图，再在可用空间内计算区域：

1. 服务入口或图标集合：参考中的 5×2 只影响候选，不会自动固定为 5 列 2 行。手机宽度（不大于 430）按 visual-design.html “金刚区与宫格入口”的公式推导：入口数、最长文案字数（`content.longest_label`，默认 4）和屏宽决定最多列数、列数、行数、分页与“全部”入口，结果写入区域的 `dock`；也可单独运行 `py -X utf8 scripts/style_match.py --dock <入口数> <最长文案字数> <屏宽>`。更宽的视口用对象数量、最小卡片宽度、间距和视口计算列数。
2. 用户明确提出“非对称指标看板”时，保留 `asymmetric`、`primary_metric_anchor`、`supporting_metrics`、`independent_context_panel` 关系。桌面根据三类内容量分配主区、辅助区和独立面板的跨度；窄屏将面板折叠或移入内容流，保持信息优先级而不是强行保留右栏。
3. 图文或杂志式页面：根据文字长度、图片数量、图片比例和视口，决定分栏或堆叠；“三列”是参考信号，图片少或屏幕窄时可以减少列数。
4. 阅读页面：以阅读宽度、章节层级和渐进披露为核心，不能为了复刻参考图而添加空卡片或装饰列。
5. 其他页面：以对象类型、扫描顺序和最小可读宽度计算区域，输出可解释的自适应方案。

每个区域至少说明 `id`、`role` 和它与其他区域的关系；每次改变列数、位置或比例都在 `decisions` 写原因。相同 brief 在桌面与移动视口应得到不同的布局参数，除非真实内容和最小宽度证明无需变化。

## 3. 风格匹配

`references/interface-style-matrix.json` 只记录视觉信号和边界。匹配器从显式风格词、业务气质、对象角色、可读性和无障碍风险生成 2–3 个候选，每个候选给出理由、适用角色和风险。候选是设计方向，不是自动执行命令。

MorphIcons、Lordicon、Hover、Loop、Spring 等动效参考写入 `evidence.motion_signals`，再转换为 `interaction` 决策。默认优先状态反馈和短时形变；循环、悬停和弹性物理只在 brief 提出后作为候选，并在审批中确认触发器、作用范围和 `prefers-reduced-motion` 降级。动效不能承担唯一语义，也不把某个组件库的默认动效复制成全站规则。

控件图标、导航、标签、菜单、按钮、工具栏、表格和表单继续使用全站统一的 2 像素线性矢量。候选风格默认只作用于入口图标、指标图形、空状态、品牌主视觉和装饰元素；范围必须在审批里逐项确认。毛玻璃、黏土、软糖、2.5D、拟物纹理等不自动改变页面底色、控件表面或数据表格。

## 4. 冲突处理

- 显式业务关系优先于参考排列；可读性、对比度、触控目标和系统既有规则优先于装饰风格。
- 用户明确的风格词优先于弱语义推断，但仍要检查它适用的资产角色；“毛玻璃图标”不等于“毛玻璃全页面”。
- 参考中的渐变、半透明、材质或动态效果只有在用户明确确认且不违反本次主题规则时才进入具体设计；参考里的深色界面只作深色主题的版式参照，色板仍取主题库的 `dark` 映射，不照搬参考的颜色；产品前端始终同时有浅色与深色两套主题，页面仍遵守扁平线性和状态可读性规则。
- 当多个参考互相冲突时，保留共同的语义目标，分别列出候选，不用平均混合成一套不可解释的视觉。

## 5. 用户确认门

匹配结果默认写入 `approval.status = "pending"`。确认对象包含：

```json
{
  "status": "pending",
  "candidates": ["gummy", "inflated-3d", "flat-illustration"],
  "selectedStyle": null,
  "scope": {
    "controls": "line-vector",
    "entryIcons": null,
    "metricIllustrations": null,
    "heroDecorations": null,
    "emptyState": null
  }
}
```

确认前只给用户看：页面意图、语义关系、自适应布局候选、2–3 个风格候选、影响范围和风险。不得正式调用 Imagegen、生成资产、修改页面代码或发布。只有用户选定风格和作用范围后，才把 `status` 改为 `approved`，再进入视觉稿、提示词和实现阶段。
