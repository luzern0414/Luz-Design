原型参考实现与组件模板库

适用范围

产品开发用的前端界面网页原型的参考实现。现行的参考实现是本技能的模板库：templates/app（手机端）与 templates/web（桌面端），各有首页、列表、订单、我的、智能体、卡片画廊五页加组件库，组件带编号，可直接取用。原型是参考，不是交付模板；页面、动作、数据与权限由系统技能定义，外观与实现由视觉技能负责，划线见 references/ui-ownership.md。

工作流程

  1. 读系统技能交来的功能清单与页面清单，列出要做的页面、入口、返回关系与状态；没有对应业务的页面不做。
  2. 打开 index.html 预览五类页面，对照页面选起点；组件用 scripts/template_registry.py list 与 show 按编号取用。
  3. 把商品、订单、客户换成真实对象，删掉没有业务用途的槽位；颜色取 references/themes.json 的主题，素材按图像规则重新生成。
  4. 主任务贯通后再扩展：每个页面逐项过状态（加载、空、错误、成功、无权限、长内容），再做窄屏。
  5. 交付运行成品时走 scripts/frontend.py 的封存与审阅，规则见 组件复用。

核心规则

一、定位：参考，不是模板

模板库回答“这类页面的结构、组件与交互怎么落成”，不回答“这个产品该是什么样”。构图、配色、素材与文案按本次业务重做；不把模板里的商品、订单、数据当作业务事实。

二、模板库怎么用

  • 页面可双击直接打开，共用 kit 的令牌、样式与脚本；令牌由 scripts/sync_template_tokens.py 从主题表生成，不手改。
  • 组件编号形如 AP-HOME-004：端、域、三位序号，发出后不改不复用；用户报编号时按编号取用，不凭印象重写。
  • 完整填写进独立页面，单字段原位改，通知与警告按硬规则；详情就近展开或进入独立详情页并恢复来源。

三、规格与验收

  • 字号、字体、图标、顶部与底栏、卡片与标题位置执行 成品硬性规定；取值见 视觉基础。
  • 实际看图并操作：首项、中间项、末项和长列表，目标宽度与更窄宽度，减少动态效果下的状态。

平台矩阵

端画布主导航起点
手机端三百九十宽单列，触控底栏三至五项，全宽贴底templates/app
桌面端一千四百四十宽，宽屏做比较与关联详情左侧图标与标签同排，图标约为标签字号templates/web

案例样本

首页的八宫格入口、礼券领取后收起、横滑商品卡；列表的分段加单行筛选、就近展开与独立详情；订单的状态分段、取消确认与独立售后填写页；智能体的思考、工具调用、流式回答与审批卡。每个示例都是模板库里可运行的页面，编号见 references/template-registry.json。

输出契约

  • 交付可运行的页面与源码、素材清单、组件来源与许可，以及目标宽度截图和实际操作记录。
  • 使用模板库的页面，在 component-sources.json 登记模板库的版本与所用文件的哈希；素材清单见 kit/assets/manifest.json。
  • 没有服务端的演示明确写出数据范围，不伪造上线能力。

质量门禁

  • 硬规则逐项核对，例外须用户对具体范围二次确认。
  • scripts/frontend_rules.py 零违规，scripts/template_registry.py check 编号通过。
  • 体验、智能体可操作性、开发复现三轴分别提供真实证据；无障碍另查。

交接规则

系统技能交页面清单、入口表与状态；视觉技能交可运行成品与验证记录。功能变更退回系统技能，视觉与实现变更留在视觉技能。后端接口与数据由开发技能承接。
