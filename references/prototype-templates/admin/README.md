# 后台参考实现（admin）

后台原型的机制与参考写法。引擎共用部分见 `../engine/ENGINE.md`，方案与分工见 `../README.md`，规格结构见 `../schema/prototype.schema.json`。生成：

```text
py -X utf8 scripts/build_prototype.py <规格.json> [--out 输出.html] [--content 内容模块.js] [--check]
```

## 参考，不是模板

行业不同，后台的菜单、工作台和页面组成就不同：门店后台的第一件事是今天的预约和核销，电商后台是待发货和库存，内容后台是待审核。**这个目录不规定后台应该有什么**；它给的是一套可以直接用的机制，和几份“某个行业的一种答案”。

| 可以直接拿来用的机制（与行业无关） | 只能当参考的内容与结构（某个行业的一种答案） |
|---|---|
| 外壳：侧栏（分组、折叠成图标栏、窄屏抽屉、深浅）、顶栏（品牌标识、命令搜索、通知下拉、账号菜单）、多标签页（各自保持页面栈与列表状态）、面包屑（只在二级页出现） | 示例里的菜单、分组名、页面清单、各页的列与筛选 |
| 配置面板：外观、主题色、图标风格、侧栏深浅、密度；场景面板与逻辑面板（来自引擎） | 示例里的数据、状态映射、经营设置项、文案、指标口径 |
| 页面的写法：`list`（列表）、`dashboard`（工作台）、`form`（表单）、`settings`（设置）、`detail`（居中详情）、`result`（结果页）、`blocks` / `custom`；动作、批量、行内开关、导出、分页、只读角色 | 工作台里放哪些指标、哪些模块、先后顺序 |
| 规格校验与生成器（只查结构：引用是否成立、入口规则、控件规则） | “后台应该有工作台、订单、商品”——**没有这样的默认**，也没有任何必填的菜单、页面或组件 |

用法：先问“这个行业的管理员第一件事是什么”，再按项目的功能说明（Luz-System 的功能清单与入口表）列菜单和页面，用页面范式库选范式，最后才去机制里挑要用的页面写法；需要库里没有的整页，写 `custom`。校验器报错写的是“规格引用了不存在的……”，不是“模板必须包含……”。

两份示例用同一套机制长出不同的后台，见 `../examples/`：

| 示例 | 行业 | 菜单 | 工作台 |
|---|---|---|---|
| `generic-admin` | 商品与订单运营 | 工作台 / 交易（订单、商品）/ 会员与营销（会员、营销活动、评价）/ 财务与权限（手风琴父项：财务对账、角色权限、操作日志）/ 系统设置；通知中心与个人中心从顶栏进入 | 指标卡（销售额、订单数、客单价、新增会员、退款额，较上期变化）→ 趋势 + 渠道占比 → 待办 + 商品排行 → 最新待发货 |
| `service-admin` | 到店服务（预约、排班、核销） | 今日台 / 预约与排班（预约日历、员工排班）/ 客户与服务（客户档案、服务项目、核销记录）/ 门店设置；**没有商品和订单** | 预约数、到店率、核销次数、核销金额 → 今天的预约日程 + 待办（待核销、未到店、沉睡客户）→ 服务热度 + 预约来源 |

## 文件

```text
admin/
  build_kind.py     生成器插件：check(spec, ctx) 只查结构；build(spec, ctx) 返回 css / js / stage_html / cids
  admin.css         样式（外壳、页面框架、表格、表单、仪表盘、居中面板、响应式）
  stage.html        中间舞台的外壳骨架（预览宽度工具 + #adApp）
  js/               运行时，按文件名顺序拼接：00 基础 10 外壳 20 列表 30 表单 40 设置 50 工作台 60 动作与详情 70 页面与状态 90 注册与事件
  engine-requests.md  向引擎提过的 12 条请求与落地情况（都已由引擎实现，后台已接入，绕法已删除）
```

## 规格怎么写

顶层字段用共用 schema 里的：`meta`、`theme`、`nav`、`shell`、`pages`、`roles`、`scenes`、`actions`、`data`、`flows`、`rules`、`statuses`、`directory`、`content`。后台专属的东西放在 `nav` 项、`pages[]`、`shell`、`data` 和 `theme` 里（这些对象允许多出字段；`theme` 里的 `sidebar`、`density` 是后台的默认值）。每页的 `logic`（来源、返回、完成后、主操作、规则）是生成器必填的，右栏“本页逻辑”渲染它。

### 侧栏 `nav[]`

菜单树：带 `page` 的是标签（一级页），**不带 `page`、带 `children` 的是分组节点**，可以嵌套。每项 `{id, name, icon?, page?, children?, badge?, hidden?}`，按数组顺序排。

- **分组标题**：分组节点不写 `icon`，画成一行分组标题，它的子项是一级项（要写线性图标 `icon`，库里 `LIB.LINE` 的名字）。
- **手风琴父项**：分组节点写了 `icon`，画成可展开的一级项，子项是二、三级项（**不放图标**）；宽屏同一时刻只展开一个，打开页面时自动展开当前页所在的分支，祖先项用较弱的方式高亮；图标栏和窄屏抽屉里点父项出悬浮菜单。有子项的项只负责展开收起，要有概览页就把“概览”放在子项第一位（分组节点不能同时写 `page`）。
- **规则**（生成器报错）：分组只在组内有两项及以上时使用，分组名不能与组内唯一一项同名；最多三级（分组标题不算层级）；不用扁平的 `group` 字段。
- `badge` 是 `K.data` 里的数字路径，或 `{count: "数据路径", where: {字段: 值}}`（实时计数）。`hidden: true` 的项不画在侧栏，但仍是一级页（从顶栏通知、账号菜单进入，也会进多标签页）。每个一级页都要出现在 `nav` 里，且页面要写 `tab: <nav id>`（目录按它分组）。

### 页面 `pages[]`

`id name type tab` 加下面之一或几个内容字段，`roles`、`scenes`、`links`、`logic`、`actions`、`empty`、`maskClose` 等共用字段同引擎（表单面板与确认类面板写 `maskClose: false`）。

| `type` | 含义 | 面包屑 |
|---|---|---|
| `tab` | 一级页，只由侧栏或标签页切换进入 | 不放 |
| `sub` | 二级页（长表单、子页），压栈，保留来源 | 放：`侧栏项 › 本页名` |
| `result` | 结果页（成功、空、无权限），压栈 | 放 |
| `sheet` | **居中面板**（详情、编辑、确认），原生 `<dialog>` + `showModal()`，有遮罩、焦点陷阱、Esc；`layout` 只能是 `center`（不用右侧抽屉） | 不放 |

`panel` 这个 schema 里的类型在后台不单独使用（写了会报错，改写 `sheet`）。`title` 是 `{字段}` 模板（取记录里的字段）；一级页不要写与侧栏同名的 `title`；`crumb`（一级页上写了会报错）；`titleNew` 是“新建”时的标题。`actions[]` 是页面顶部操作：最多 1 个主按钮（`kind: "primary"`）加 2 个次按钮，每个带 `icon`，写 `go` / `sheet` / `tab` / `act` / `toast` 之一，改数据的写 `write: true`（只读角色与“禁用”状态下会灰掉并写原因）。

**跳转边**：`list` 的行操作与批量操作、页面顶部操作、工作台待办与预警、表单保存后去哪（`thenNew`、`go`）、详情动作、结果页按钮产生的跳转，由 `build_kind.py` 的 `edges(page, spec)` 钩子自动报给生成器，用于孤岛检查，规格里不用手写 `links`（`links` 仍可用于 `custom` 页面自己产生的跳转）。`blocks` 项可以写可选的 `id`、`name`（同一页内 `id` 不能重复），场景面板的“模块显示”用它做名字。

### `list`：列表页

```jsonc
"list": {
  "data": "orders", "noun": "订单", "nameTpl": "{no}", "select": true, "export": {"file": "订单"},
  "columns": [{"key", "label", "type", "sort?", "width?", "align?", "map?", "sub?", "unit?", ...}],
  "tabs": {"key": "status", "map": "orderStatus", "order": ["pending", "..."], "more": ["closed"], "default": "pending", "all": "全部"},
  "defaultSort": {"key": "createdAt", "dir": "desc"}            // 或 {标签值: {...}, "__all": {...}}
  "filters": {"search": {"keys": [], "placeholder": ""}, "primary": [筛选...], "more": [筛选...]},
  "bulk": [动作...], "rowActions": [动作...], "moreActions": [动作...], "sum": ["gross"], "pageSize": 20
}
```

- **数据**：`K.data` 里 `list.data` 路径下的数组，每行要有 `id`。状态映射与选项表放 `data.maps.<名>`（`{值: {label, tone}}`，`tone` 取 `ok wn dg in mu`）和 `data.options.<名>`（`[{v, label}]`），列、标签、筛选、表单用名字引用，同一状态全系统同名同外观。
- **列类型**：`text`（居中）`long`（左对齐、省略、悬停全文）`num` `money`（右对齐、等宽数字、两位小数，单位写表头）`status` `tag` `date` `datetime`（两行）`person`（默认动物头像 + 名字 + 副行）`thumb`（库素材图）`two`（主 + 副）`switch`（行内开关）`rating`。表头居中；列宽 `width`；8 列以上自动冻结勾选列、对象名列和操作列，容器内横向滚动。
- **默认视图**：`tabs.default` 打开即是最需要处理的子集，“全部”放在标签末尾；标签带数量，数量为 0 的弱化，终态收进 `more`；`defaultSort` 可按标签分别写。筛选外露最多 4 个（搜索 + 3 个），其余放 `filters.more`（“更多筛选”，角标显示已生效数）；生效的筛选以可移除标签显示；搜索即输即查，没有“查询”按钮。
- **分页**：默认每页 20 条，可选 10 / 20 / 50 / 100（用户选过的条数本次会话记住），共 N 条、上一页、页码（超过 7 页折叠）、下一页、超过 5 页加“跳至”；改筛选、排序、条数回到第 1 页；`sum` 列出要合计的金额列，表尾固定“本页合计”（勾选后变“已选 N 项合计”）并另有一行全部筛选结果合计。
- **批量栏**：勾选后在工具栏原位置替换为“已选 N 项 + 批量操作”，不把表格向下推；批量操作的 `when` 不满足时按钮置灰并写原因。
- **动作** `{id, label, ...}`：`sheet`（开居中面板，带记录 id）`go`（压栈）`tab`（切侧栏）`act`（调命名动作）`patch`（改字段）`inc`（数值加减）`append`（给记录的 `log` 追加一条）`log`（写操作日志，需要 `data.audit` 数组）`confirm: {title, text, ok}`（居中确认框）`danger` `when`（行字段条件，不满足时置灰并显示 `whyNot`）`toast` `close` `write: false`（只读也能点）。行内文字操作不加图标；外露最多 3 个，其余放 `moreActions`（“更多”菜单）。
- **行内开关**（`switch` 列）：悲观更新——点击后进入处理中并忽略重复点击，成功才切换并轻提示；失败保持原状、在原位写原因（原因来自业务场景或列的 `guard`）。
- **导出**：`export` 在工具栏出现“导出筛选结果（共 N 条）”，点开是预览面板：文件名带中文标题与范围，表头是中文，状态翻译、金额两位小数、不带内部编号；容器带 `data-export-preview`。
- **窄屏**：舞台宽度小于 640 时表格每行转成卡片，操作仍可用；中等宽度在容器内横向滚动。没有数据、筛选无结果、加载、失败各有状态页。

### `dashboard`：工作台

`range`（页面级时间范围，统一控制所有卡片，卡片上不再写时间范围）、`kpis[]`、`alerts[]`、`sections[]`。

- 指标 `{id, label, calc: {op, src, field | num+den}, format, unit, icon | tile, bad?, quiet?}`：`op` 取 `sum avg last ratio`，`src` 是按日的数组（每行有 `date`）；自动算较上期的涨跌；`bad: true` 表示下降是好事；`quiet: true` 的指标为 0 时合并成一行“暂无异常”。点少于 7 个不画迷你趋势。
- 预警 `{id, kpi, deltaGt, text, tab, preset}`：指标较上期涨幅超过阈值时出现一条可关闭的提示，点“去处理”直达已筛选好的列表。
- 模块 `kind`：`trend`（折线，悬停与方向键读数，多指标切换，点少于 3 个不画折线）`donut`（占比，点图例显隐，只有 1 类不画）`rank`（排行，按数值降序）`todo`（待办：数量 + 直达 `tab`+`preset`，`preset` 可带 `tab`、`filters`）`feed`（动态）`agenda`（某一天的日程：`src`、`where`（可用 `"@today"`）、`time`、`row`、`sub`、`status`）。`w` 取 4 / 6 / 8 / 12（12 栏栅格）。

### `form`：表单（`sub` 页是整页，`sheet` 页是居中面板）

`record: {data, list, defaults}`（编辑哪条记录；传 `new` 或不传是新建）、`sections[].fields[]`、`submit: {label, cancel, toast, then, thenNew}`、`log`、`idPrefix`、`stamp`（保存时写时间的字段）、`patch`（保存时一并改的字段）。字段类型：`text textarea number money select radio switch tags images slider date ro`；`required`、`max`、`min`、`pattern`、`msg`、`hint`、`default`。必填标红星、失焦校验、提交时汇总并定位第一个错误、字数计数、金额失焦补两位小数；保存失败保留输入并在顶部写原因。面板里的表单点遮罩不关闭，Esc 与取消可关闭，关闭后草稿仍保留（取消则丢弃）；图片只能选库素材里的图。

### `settings`：设置页（经营设置闭环）

`{data, groups: [{id, label, sections: [{title, items: [...]}]}]}`，数据在 `K.data.<data>`，来源在 `K.data.<data>_src`（`default` / `global` / `store`）。每项 `{key, label, impact, type, unit, min, max, step, options, default, money?, scope?}`：`switch` 直接生效不放保存按钮；`number` / `radio` 行内修改，写明允许范围，单选写中文选项名；`money: true`（影响资金）先弹确认框：写清改前改后与影响范围，必填原因，验证身份（演示环境任意非空）；保存后提示“已生效，只影响之后的业务”；非默认值可“恢复默认”；修改写进 `data.audit`（操作日志页读它，闭环）。

### `detail`：居中详情（写在 `type: "sheet"` 的页里）

`{data, list, head: {status, map, big, sub}, sections: [{title, kv | table | timeline}], actions: [...]}`。详情的底部动作同列表动作；点遮罩可关闭，关闭后回到列表原位置，保留筛选、排序、页码和状态标签。

### `result`：结果页

`{tone: ok|dg|wn|empty|denied, title, text, facts: [[名, 值]], actions: [...]}`，至少一个下一步（不让用户无路可走）。

### `blocks` 与 `custom`

与小程序一致：`blocks[]` 按库组件编号拼装（`cid`、`gap`、`heading`、`custom`，覆盖键 `text img go back tab sheet act toast attrs class hide`）；`custom: "名"` 引用内容模块 `pages[名](frame, ctx, args)` 返回的 HTML。库里的整页组件（角色权限矩阵、日程周视图、员工排班表、通知中心、个人资料）可以直接放进 `blocks`，它们自带交互。

### 外壳

- **布局**：顶栏（折叠按钮、品牌标识 + 系统名、全局搜索 `Ctrl K`、测试环境标识、通知、账号）→ 左侧栏 | 标签页条 → 面包屑（只在有二级页时出现）→ 内容区（单独滚动）。侧栏底部一行版本号（`app-version`），点开版本信息面板。左右两栏的宽度由 `K.kind({layout})` 声明（左 264、右 320），外壳页头的“左栏”“右栏”按钮可以折叠它们，两栏都折叠就是“只看舞台”；不覆盖 `.pt-layout` 的列宽。
- **按舞台宽度响应，不是窗口宽度**：≥ 960 完整侧栏；640–960 图标栏（悬停显示名称，父项点开悬浮菜单）；< 640 侧栏收进抽屉、表格转卡片。预览区上方有“预览宽度”工具（自适应 / 平板 820 / 手机 390），看窄屏不必缩窗口。窗口 < 910 时引擎把三栏改成上下排。
- **多标签页**：每个侧栏标签是一个“工作区”。页面栈由引擎保留（`K.kind({keepTabStacks: true})`：切换标签保留各自停在的二级页，再点当前标签回到它的根页）；列表的筛选 / 排序 / 页码 / 勾选、表单草稿、滚动位置各标签自己留着；首页标签固定，其余可关闭，关闭即丢弃该标签的状态，“更多”菜单有关闭其他、关闭全部；最多 15 个，超出关掉最早的。
- **顶栏弹出**：通知下拉（红点与未读数一致、全部已读）、账号菜单（外观三选一、个人资料、退出登录先确认）、命令面板（输入页面名，结果带层级路径，↑↓ 选择，Enter 打开，Esc 关闭）。
- **居中面板与确认框**：都是引擎的原生 `<dialog>`（`showModal()`、焦点陷阱、Esc、关闭前 150 毫秒退出动画——判断“是否已关闭”要同时看 `.closing` 类）。详情面板点遮罩可关；表单面板和确认框 `maskClose: false`，点遮罩或面板外不关闭；表单面板有未保存内容时 Esc、× 先问“放弃未保存的修改？”（`onBeforeClose`，确认框用 `stack: true` 叠在表单上），取消按钮直接丢弃草稿。影响资金的修改用 `K.confirm({fields})`：必填原因、验证身份，不通过不关闭。从详情面板里发起的二次确认也叠在详情上。
- **局部重画**：列表（搜索即输即查）、设置、工作台的交互走 `K.render({part})` → `renderPart`，元素上的 `data-fk` 让引擎恢复焦点与光标，不整页重画。
- **浅色与深色**：样式用 `--ad-*` 令牌写成，深色只换令牌；组件库已有真令牌的深色层（给 `<html>` 加类 `dark`、`light` 或 `data-theme`，引擎写 `html[data-theme]`），库组件在深色下自己换色，后台不再做滤镜；主题色用库的 `data-lt`（`LIB.applyTheme` 只写这个属性，引擎也对弹层调用），派生令牌（高亮底、高亮字）声明在 `#root` 与 `.pt-dlg` 上。**深色里有理由保持原样的例外**见组件库 `README.md` 第六节“例外清单”：压在主题色或状态色实色底上的白字；登录二维码（白底）；后台深色侧栏变体（AD-NAV-002，浅色里也是深的）；深底舞台与第一代的暗金奢品卡、大图沉浸卡；照片上的遮罩与压图文字；纯黑阴影与白色高光；金、沙、棕、青灰等彩色点缀（图表系列、默认头像配色）；默认头像和空状态插画的内部色；AD-STATE-002 的 403 装饰数字（对比度刻意低）。这些在深色下看起来仍是原色，不是漏改。
- **动效**：时长只用 100 / 150 / 200 / 300 毫秒四档（`--mo-*` 变量），退出取进入的 75%（抽屉进入 200、退出 150）；只动 `transform`、`opacity`、颜色；不用 `transition: all`；循环的转圈与骨架闪动不算进入退出；减少动态时所有过渡与动画降到近 0。
- **固定定位**：本模板没有 `position: fixed` 的块；抽屉、下拉、通知都是 `.ad-app` 内部的 `position: absolute`；遮罩与居中面板由引擎的原生 `<dialog>` 承担（它自己是 `position: fixed`，属引擎）。
- **无障碍与审计**：外壳工具标 `data-shell`；产品界面的控件都落在带 `data-cid` 的元素里（侧栏 AD-NAV-001/002、顶栏 AD-NAV-003、标签页 AD-NAV-005、面包屑 AD-NAV-004、列表各区 AD-TBL / AD-FLT / AD-NAV-007、详情 AD-FB-003、表单面板 AD-FB-009……；`<dialog>` 元素本身的 `data-cid` 由引擎写），`audit_rendered.py --library luz-kit --min-font 12` 在 1440 与 390、浅色与深色下对两份示例逐页通过。整页都是库组件的页面（预约日历、员工排班、角色权限、通知中心）里，库自己的状态色对比度（4.33:1，库的 ok 色压在 ok 浅底上）与 20px 的触控目标属组件库的已知差距，测试里不算后台模板。

## 运行时接口

`K.ad`：`activate(标签 id, preset?)` 切侧栏标签（页面栈由引擎保留）、`closeTab(id)`、`lstate(页面 id)`（列表状态：`tab q f sort page size sel`）、`draft(页面对象, 参数)`（表单草稿）、`run(动作, 行数组)`、`outcome(场景 id, 成功回调, 名称)`、`state`（外壳状态）。内容模块可以用 `K.ad.fmt` 与 `K.ad.rows(路径)`；演示数据在内容模块的 `init(data)` 里生成（“重置演示数据”会重新调用）。

## 没做的与限制

- 列设置、列宽拖拽、地址栏参数（`page`、`page_size`、状态标签）：本次没做；引擎路由只同步页面 id。
- 时间范围：主栏是预设下拉（今天 / 近 7 天 / 近 30 天），自定义日期区间放在“更多筛选”里。
- 删除与停用的“5 秒撤销”没做（示例里没有删除，用状态流转代替）。
- 手风琴在图标栏里的悬浮菜单只有一级；三级项在窄屏抽屉里按缩进展开。
- 库里整页组件（日程周视图、员工排班表等）自带的是示例数据，只能用 `blocks` 覆盖改文字，不接 `K.data`；要接数据写 `custom`。
