# 花店小程序示例（florist-mini）

这是**参考，不是模板**：一个虚构的花店小程序“花间集”，用来说明“专属页面怎么用 mini 模板的机制做出来”。它是垂直电商的**一种答案**，页面清单、首页组成、入口与文案都不是默认值；行业不同，首页的功能、模块和布局就不同，由项目的功能说明（Luz-System 的功能清单与入口表）和行业决定。花店专属的一切（品牌、商品、页面渲染函数、文案、素材）只放在本目录里，通用模板（`engine/`、`mini/`、`schema/`）里没有。

它由三样东西生成，没有手写的整页 HTML：

| 文件 | 内容 |
|---|---|
| `spec.json` | 规格：30 个页面与弹层的类型、所属标签、`logic`（来源、返回、完成后、主操作、规则、状态、后台维护）、`links`（自定义渲染里的跳转，给生成器查孤岛与引用）、`flows`、`rules`、`statuses`（订单状态机）、`scenes`、`directory`，以及演示数据 `data`（商品、地址、门店、优惠券、订单、评价、协议文字） |
| `content.js`、`content.css` | 内容模块：页面正文的渲染函数（`pages`）、业务动作（`acts`：加购、结算、支付、取消、售后……）、业务计算与状态。类名一律带 `fl-` 前缀，事件一律用引擎的 `data-pt-*` 属性 |
| `assets/` | 素材（WebP，共约 0.5 MB）：花店专属的 6 个入口图标 × 3 种风格、9 张商品图、2 张头部背景；库自带的 10 个入口图标不重复放 |

## 重新构建

```text
py -X utf8 scripts/build_prototype.py references/prototype-templates/examples/florist-mini/spec.json --out <输出.html>
py -X utf8 scripts/build_prototype.py references/prototype-templates/examples/florist-mini/spec.json --check     # 只校验
```

输出是单文件 HTML（约 1.7 MB），默认写到 `references/prototype-templates/dist/`（`.gitignore` 已忽略，不入库）。测试：`py -X utf8 -m unittest scripts.test_prototype_florist`（Playwright + Edge，约 25 秒；没有浏览器时流程测试会跳过并写明原因）。

## 机制与内容怎么分

- **模板（mini）画**：手机框、状态栏与胶囊、导航栏（含返回）、标签栏与角标、弹层（原生 `<dialog>` + `showModal()`）、轻提示、头部背景（渐变/浅色/图片）、空/加载/失败/无权限/禁用状态页。
- **规格写**：每页是什么类型、属于哪个标签、从哪来到哪去、有哪些规则与状态，流程、场景、状态机。
- **内容模块写**：页面里画什么。花店的页面基本都是专属布局，所以走 `custom`；有现成库组件贴合的地方直接用 `K.block('MP-…')`：搜索页用 `MP-NAV-006`、购物车免配送费进度用 `MP-MKT-004`、商品评价摘要用 `MP-GOODS-004`、售后申请用 `MP-ORD-014`、评价用 `MP-ORD-015`、地址编辑用 `MP-FORM-005`。自定义渲染里的每一块都包着最接近的库组件编号的 `data-cid`（`display: contents`，不影响布局），审计按它核对控件来源。

## 首页组成

首页（`home`，一级页，带头部背景）从上到下：

1. **顶部**：配送地址与门店合成**一个**入口（“配送至 建国路 88 号 · 建国路店营业至 21:00”，点开是“配送地址与门店”页），下面是搜索框（一个主入口）。
2. **活动位**：一张活动卡“春日鲜花节”，整张卡不可点，只有“去选花”一个按钮；首屏营销模块不超过 2 个（活动卡 + 新人礼券）。
3. **截单提示**：当日 17:00 截单（信息类，一行）。
4. **入口宫格**：只放需要分发的 5 条业务线——同城鲜花、节日礼盒、绿植盆栽、周期订花、花艺定制。收藏、优惠券、会员、门店不放首页（在“我的”或顶部地址入口里），订单与账户类入口也不放首页；分类、购物车、我的已有标签，首页不重复。
5. **新人礼券**：领取后整块收起，下方上移（场景“新人礼券”可切换）。
6. **当季热卖**：模块标题 + “全部”，下面是只在本模块内筛选的标签（热销、新品、礼盒、绿植），再是两列商品卡；底部“没有更多了”。

## 页面（30 个）

- 一级页（4，标签栏）：首页、分类、购物车、我的
- 浏览与选购：搜索、商品列表、商品详情、商品评价、配送地址与门店、选择规格（弹层）
- 下单与支付：确认订单、选择送达时间（弹层）、选择优惠券（弹层）、确认支付（弹层）、支付结果（成功 / 确认中）、支付失败
- 订单与售后：全部订单、订单详情、取消订单确认（居中弹层）、申请售后、评价
- 我的：收货地址、选择收货地址、编辑地址、我的优惠券、我的收藏、会员中心、设置、协议与须知、联系客服

## 流程

`flows` 里有 6 条，左栏“场景”页签的“流程直达”可以一键跳到起点：浏览选花、下单到支付、支付失败重付、取消订单、申请售后、评价。规则照 016 原型：

- 标签页只由标签栏切换；二级页隐藏标签栏，左上角返回到来源页；每个标签独立页面栈。
- `go` 不能去标签页。结算从购物车或详情“立即购买”进入，进入时记下发起处；支付成功后用 `replace` 换成结果页，结果页“完成”用 `done` 回到发起处（购物车根页或商品详情），不是首页，也不切换标签。
- 从订单列表“去支付”进入的支付，结果页是 `go` 进来的，“完成”就是返回订单列表。
- 取消订单、申请售后、评价改的是同一份订单数据，订单状态机见右栏“状态流转”（待付款 → 备货中 → 配送中 → 已送达 → 已完成；退款中；已取消）。

## 场景

购物车（有商品 / 空）、新人礼券（未领取 / 已领取）、支付结果（成功、处理中、失败：支付超时、用户取消支付、余额不足）、商品库存（有货 / 已售罄，详情底栏变“到货提醒”）、配送范围（范围内 / 超出范围，结算页提示并禁用提交）。另有引擎自带的“本页状态”（加载、空、四种失败原因、无权限、禁用）与全局项（网络、减少动态、重置演示数据）。

## 已知限制

- 导航栏标题是页面固定的名字，商品列表这类标题取自进入参数的页面，把标题写在了正文顶部。
- 左栏页面目录只能列页面，不能带参数，所以“订单详情 · 配送中”这类变体用流程或测试里的 `K.jump(id, 参数)` 直达。
- 深色外观对组件库部分是滤镜近似（见 `engine/ENGINE.md`）。
