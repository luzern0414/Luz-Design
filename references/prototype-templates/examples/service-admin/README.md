# 示例：到店服务运营后台（预约、排班、核销）

同一套后台机制长出的另一种后台：**没有商品、没有订单**。菜单是今日台 / 预约与排班 / 客户与服务 / 门店设置，工作台第一屏是“今天的预约与核销”。它比 `../generic-admin/` 简单，作用是让人看到：菜单、工作台、页面组成由行业决定，外壳、配置面板、逻辑面板、列表、表单、设置这些机制可以原样复用。

```text
py -X utf8 scripts/build_prototype.py references/prototype-templates/examples/service-admin/spec.json --out service-admin.html
```

- `spec.json`：规格（11 个页面，主要 10 页 + 1 个无权限结果页）；`content.js`：内容模块（虚构的演示数据）。
- 默认蓝色主题 + 深色侧栏 + 线性图标风格，和通用示例形成对比。

| 菜单 | 页面 | 写法 |
|---|---|---|
| 今日台 | `today` | `dashboard`：预约数、到店率、核销次数、核销金额；今天的预约日程（`agenda`）+ 待办（待核销、今天未到店、沉睡客户）+ 服务热度排行 + 预约来源占比 |
| 预约与排班 › 预约日历 | `calendar` | `blocks`：库组件 AD-FLOW-005（日程周视图） |
| 预约与排班 › 员工排班 | `roster` | `blocks`：库组件 AD-FLOW-006（员工排班表） |
| 客户与服务 › 客户档案 | `clients` + `client-detail`（居中面板） | `list`：默认只看活跃客户；补登到店 |
| 客户与服务 › 服务项目 | `services` + `service-edit`（居中面板表单） | `list` + 行内上架开关 + 表单面板 |
| 客户与服务 › 核销记录 | `redeem` + `redeem-do`（居中面板表单） | `list`：撤销核销要二次确认；新增核销的核销码按 6 位数字校验 |
| 门店设置 | `shop-settings` + `res-lock`（无权限结果页） | `settings`：预约规则、核销规则；爽约是否扣次数属影响客户次数的项，先验证身份并写原因；只对店长开放 |

角色：店长、前台（看不到门店设置）。

菜单同样用分组节点写（“预约与排班”“客户与服务”是分组标题）；工作台各模块与两个库组件页都写了 `id`、`name`，可以在场景面板的“模块显示”里逐个关掉。
