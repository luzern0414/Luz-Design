# 参考研究协议（用 Luz-Crawl 找真实参考，量出来，再借用）

目的：设计不凭感觉。动手画之前，先拿到同类优秀产品的真实页面，把它们“量”成数据（字阶、色板、圆角、间距、留白、动效），再决定借什么、不借什么。本协议是 WORKFLOW 第 3 步（Research）的设计专用展开，仍然遵守 `D:\Codes\Luz-Crawl\references\preflight.md`：先 `run`，读正文，再 `conclude`，再 `check`，一个需求一个任务目录。

## 1 参考金字塔：四类来源，各取所需

| 层 | 来源 | 取什么 | 数量 | 工具 |
|---|---|---|---|---|
| A 规范 | 平台与设计系统官方文档（微信小程序设计指南、WeUI、TDesign、Ant Design、Material 3、Apple HIG、Carbon 等，见 `reference-sites.json` 的 `spec`） | 规则原文：尺寸、令牌、状态、动效数值 | 2–3 | `capture` 文档页，读正文 |
| B 真实产品 | 同行业 3–5 个线上产品的关键页面（首页、列表、详情、结算、空状态） | **视觉指纹**：字阶、色板、圆角、阴影、间距、留白、图片处理、动效节奏 | 3–5 | `capture` 页面 + `scripts/teardown.py` 量化；截图存档 |
| C 灵感库 | Mobbin、Refero、Page Flows、站酷、花瓣等（`inspiration`） | 构图、信息层级、营销区节奏、素材风格；**只当线索** | 5–10 张 | 能读的站点用 `capture`；被拦截的不强取，换成同类站点或让用户提供截图 |
| D 素材与方法 | 摄影、图标、插画、色板、动效库、图像生成指南（`photo`/`icon`/`illustration`/`color`/`motion`/`imagegen`） | 许可、可选的风格、实现方法 | 按需 | `capture` 许可与示例页 |

原则：B 层是主证据（真实产品怎么做的），A 层给底线（规范怎么说），C 层给线索（别人怎么排），D 层给方法。不要只看 C 层：灵感图是被挑选过的，不代表能上线的产品。

## 2 流程（照做，每步留证）

1. **选站**：打开 `references/reference-sites.json`，按任务类别取 `status` 为 `ok` 的站点；`js-rendered` 的要等脚本渲染；`blocked`、`unreachable` 的不要硬取（Luz-Crawl 不破解验证码、不绕过权限）。站点状态是 2026-11-04 核验的，超过 30 天先重新核验，不能靠旧状态。
2. **建任务**：`node D:\Codes\Luz-Crawl\scripts\luz-crawl.mjs doctor` → `begin "<主题>" --new` → `experience --query "<行业> 设计 参考"`；之后每条命令带 `--out <任务目录>`。任务目录是 `<输出根>\NNN_主题`，其下 `raw\` 存放爬取的全部内容（每页一份存档，快照在存档的 `snapshots\`），总结 html 与 `raw\` 同级。
3. **找同行产品**：用 `search bing`（或平台搜索）找 3–5 个同行业的线上产品，优先小程序截图文章、官方设计复盘、产品官网；关键词写“行业 + 页面类型 + 设计”，如“鲜花 小程序 首页 设计”“同城配送 商品详情 设计”。搜索卡片只是候选，正文确认后才算来源。
4. **采集**：对每个候选页面 `capture <网址> --out <任务目录>`，保存 HTML 快照和截图；只采公开页面，批量读取前先 `robots`；每站点少量页面。
5. **量化**：对 B 层页面逐个运行
   `py -X utf8 scripts/teardown.py <快照或网址> --width 390 --lint --md <名>.md --out <名>.json`
   （桌面端用 1280/1440）。得到字阶、色板、圆角、阴影、间距基准、对齐线数、留白比例，以及与“成熟产品常见范围”的偏差提示。
6. **对照表**：把 3–5 个产品的指纹并成一张对照表（`raw/01-research/teardown-compare.md`）：每行一个指标，每列一个产品，最后一列写“本次取值”和理由。**借用属性**写成明确的一句话（如“借它的头图占首屏 40% 的比例”），**不借**的也写（如“不借它的渐变按钮，违反规范”）。
7. **结论**：用 `crawl_preflight.py conclude` 写补充信息：每条 `findings` 写来源、事实、采用位置、采用决定；`gaps` 写没覆盖的范围（如“没能取到登录后的页面”“被拦截的站点”）。

## 3 借用与版权

- 借“属性”，不借“成品”：比例、层级、节奏、取色方法、字阶、动效曲线可以借；图片、插画、图标、文案、独有构图、品牌元素不借。
- 不模仿在世艺术家的独特风格；不复制第三方角色、标志、专有插画和受限摄影；不对被拦截的站点做绕过。
- 素材权利逐条记录（来源、许可、使用边界）；商业复用前由项目所有者确认许可。参考站点登记表里的 `licence_note` 只是首页可见的原文摘录，不是法律结论。

## 4 让“思考”进入研究：四个追问

读完参考后，动手前必须回答（写进 BRIEF，不写进成品）：
1. 这几个产品共同做对了什么？（相同的取值就是行业底线）
2. 它们各自的差异在哪？（差异就是品牌的表达空间）
3. 哪一个的哪一点，用在我们的内容和用户上会失效？（防止照搬）
4. 如果只许借一件事，借哪件？（逼出优先级）

## 5 失败与降级

- 站点被拦截或需要登录：记 `blocked`，不换用户账号、不绕过；用同类站点替代，或请用户提供截图（用户自己提供的素材可以量化）。
- 脚本渲染、正文很少：等待渲染后再采；仍取不到就只用截图做视觉对照，字阶与间距不量化，在 `gaps` 里写明。
- 没有网络或 Luz-Crawl 不可用：不用旧知识冒充新采集；回到 `experience/patterns.json` 里已验证的色板与字阶，并在结论里写“未做本次检索”。
