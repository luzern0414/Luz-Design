# Luz Design 会话模板
# 模板只是骨架，不是规范。动手前先运行 py -X utf8 scripts/context.py <任务类型>，读完规则卡（用户偏好、教训、规范原文、工具、检查）再填模板；
# 模板与规则卡冲突时按规则卡改模板内容。new_session.py 会把规则卡存进 raw/00-rules/，发布前 BRIEF 必须填写“采用的规则”。
# 每个模板以 “=== template: 名称 ===” 开始、以 “=== end ===” 结束；scripts/new_session.py 的 read_template(名称) 按名称读取。
# 修改模板时只改块内内容，不改标记行。
# 网页模板的 {{TAB_ICON}}（标签页图标 <link rel="icon"> 的地址）由 new_session.py 的 fill_icon_slots 按会话标题选图案与主题主色填入；
# 其他生成网页用 py -X utf8 scripts/new_session.py icon 页面或系统名 取得。图案与绘制规范见 visual-design.html“网页图标与品牌标识”。
# 本文件的网页模板（视觉方案总览、阅读页）是文档，只做浅色；产品界面（后台、小程序、手机网页、网站、智能体界面）的视觉与布局骨架带深色变量块与外观切换，在本技能的 references/ui-kit，其中交易与营销界面的骨架是本文件的 commerce-kit.html（产品界面，带深色变量块与外观切换，不受“只做浅色”限制）；原型的行为骨架在 Luz-System 的 templates.txt。
# 网页模板 :root 里的颜色、页面底色与层级令牌只是占位，按本次主题从 references/themes.json 取值重写；页面保留模板默认样式时 check_document.py 给出警告。

// 外观（浅色与深色两套主题）：先于样式执行。读本机记住的选择（键 luz-theme，取值 light / dark，没有这个键即“跟随系统”），
// 选了浅色或深色就设置 <html data-theme>，跟随系统时移除该属性，由 prefers-color-scheme 决定；三个 role="radio" 按钮是控件，window.luzTheme.set('system' | 'light' | 'dark') 也可调用。
(function () {
  var KEY = "luz-theme", root = document.documentElement, GROUP = '[role="radiogroup"][aria-label="外观"] [role="radio"]';
  function get() { try { var v = localStorage.getItem(KEY); return v === "light" || v === "dark" ? v : "system"; } catch (e) { return "system"; } }
  function apply(mode) { if (mode === "light" || mode === "dark") { root.setAttribute("data-theme", mode); } else { root.removeAttribute("data-theme"); } }
