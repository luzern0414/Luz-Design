# 令牌与风格包标准（v2 方案）

本页把“主题令牌、字阶、配色纪律、图标风格、审计脚本”放进一个体系里，并定义“风格包”：一套可以拆开、再搭配的选项。**数值的唯一来源仍是 `themes.json`（颜色）和 `visual-design.html`（字阶、间距、圆角、层级、动效）**；本页只定义结构、命名、搭配规则和检查，凡与规范页冲突，以规范页为准；凡需放宽规范，写进“待裁定”，由用户决定。

## 1 现状判断：强在“单个主题合规”，缺在“体系与搭配”

| 已经做得好 | 缺口 |
|---|---|
| `check_contrast.py` 对每个主题逐项查对比度、深色映射、层级阴影、10 阶单调 | 只管“一个主题合不合规”，不管“色阶质量”（亮度是否均匀、色相是否漂移）、“色相预算”“色觉差异”“主色与状态色是否混淆” |
| `make_dark.py` 用 OKLCH 推导深色，`export_tokens.py` 导出 W3C 令牌，带深色 | 令牌是平的：没有“原始值 → 语义 → 组件”三层，没有密度、关怀模式等第二维度 |
| 字阶按端定好（小程序 12/14/16/18/22/28，后台 14 基准，阅读页 Markdown 层级） | 缺“为什么是这几档”的检查（比例、行高落在 4 的倍数、字重对比）和可选的字阶方案 |
| 一套线性图标 2px，入口图标可双色或生成 | 图标风格没有成为“可选包”，没有适用范围与搭配规则，没有检查脚本 |
| 风格矩阵有 10 种素材风格与作用范围 | 没有把“配色 + 图标 + 圆角 + 层级 + 动效”合成可预览的方案；用户看不到搭配结果 |
| `audit_rendered.py`、`audit_palette.py` 审渲染页 | 缺审美体检（对齐线、间距网格、留白、圆角种类）和令牌使用率检查 |

## 2 令牌三层结构

```text
原始值 ref.*   颜色 10 阶、中性阶、间距 4–96、圆角、时长、缓动、字重          （themes.json 的 scale 与 shared；规范页数值）
   ↓ 引用
语义 sys.*     color.brand/accent/surface/canvas/ink/line/state/price、type.role.*、space.*、radius.*、elevation.*、motion.*   （每个值带 light 与 dark）
   ↓ 引用
组件 comp.*    button.primary.bg、input.border、card.shadow、tabbar.active …                （只引用 sys.*，不写原始值）
```

规则：
1. **页面与代码只取语义层和组件层**，不直接写 `#B2465F`、`12px`；原始值只出现在主题库里。
2. **语义名描述用途，不描述外观**：用 `color.brand.base`、`color.brand.press`、`color.brand.tint`、`color.brand.on`（品牌色上的文字）、`color.brand.text`（品牌色文字与图标），不用 `red-600`。
3. **模式是维度，不是另一套命名**：同一个令牌在不同模式下取不同值。模式维度：`appearance`（light / dark，必有）、`density`（comfortable / compact，后台用）、`scale`（字号档位 0.94–1.4，小程序关怀模式用）。取值放在 `$extensions.mode.<名>`。
4. **命名与 CSS 变量一一对应**：`color.brand.base` → `--luz-color-brand-base`；W3C 名里不出现点以外的特殊字符。
5. **令牌文件由脚本生成，不手改**：`export_tokens.py <主题> --out …`，并用 `--check` 校验；新增维度先改脚本与测试。

## 3 配色纪律（十条，机器可查）

出处：`visual-design.html › 主题色系统 / 取色依据`；新增的检查由 `audit_theme_discipline.py` 执行，旧的由 `check_contrast.py` 执行。

1. **从官方 10 阶色板取阶**：主色取白字达 4.5:1 的一阶，按压取下一阶，浅底取第 1 阶，浅底上的主色文字取按压阶；不凭感觉调深调浅。（`check_contrast.py`）
2. **色阶质量**：10 阶亮度逐阶下降且步幅均匀（最大/最小步 ≤ 2.2），色相漂移 ≤ 12°，彩度单峰。（新）
3. **同一色相家族**：主色、按压、浅底、色阶第 6 阶色相互差 ≤ 12°。（新）
4. **中性色染色有上限**：canvas、surface、navBg 要么中性（彩度 < 0.02），要么与主色同色相且彩度 ≤ 0.03；正文三档字色彩度 ≤ 0.03。（新）
5. **色相预算 ≤ 7**：主色、点缀色、四个状态色、价格色，没有第 8 个有彩色相。（新）
6. **区分度**：主色与危险色、价格色相距 ≥ 20°（否则标“家族重叠”提示）；主色与点缀色用邻近色（25°–60°）；状态色两两 ≥ 25°。（新）
7. **色觉差异**：成功色与危险色在红绿色盲模拟下 ΔE ≥ 8；不足时状态必须带图标或文字。（新）
8. **面积预算（60-30-10）**：中性色 ≥ 60%，主色面积 ≤ 约 10%（品牌主卡屏 ≤ 约 30%），点缀色不与主色争夺。（`audit_palette.py` 查渲染页）
9. **层级可见**：canvas 与 surface 的亮度比 1.02–1.20，发丝线对 surface 对比 1.1–1.6，浅底阶能被看见（ΔE ≥ 3）。（新）
10. **深色是第二套，不是取反**：深色底亮度 L 0.12–0.30，深色主色与浅色主色亮度差 ≤ 0.15，深色品牌文字色相与浅色一致。（`check_contrast.py` + 新）

## 4 字阶纪律

数值（`visual-design.html › 字体与字号 / 七级字体角色 / 小程序字阶`）不变：小程序 12 / 14 / 16 / 18 / 22 / 28（大号数字 28/700 每屏一个），后台以 14 为基准，网站与阅读页下限 14，阅读页用 Markdown 层级（桌面正文 18、手机 16）。本页新增三条纪律与一个可选方案：

1. **比例检查**：相邻档比例落在 1.125–1.33，整体接近一个模块比；否则合并相近档，不增加新档。
2. **行高落在 4 的倍数**（节奏）：12/16、14/20、16/24、18/26（取 28）、22/28、28/36；中文正文行高 1.5–1.8，不加字间距。
3. **字重成对**：400 + 600 为日常，700 只给 ≥22 的数字与主标题；一屏不出现第三个字重。
4. **可选字阶方案**（只改字重对比与行高，不新增字号档，不越出规范的字号集合）：
   - `standard` 标准：规范原样；
   - `compact` 紧凑：后台密度（正文 14/20、表格行 44–48），用于 admin 与 web 表格；
   - `bold` 强对比：标题与数字更多使用 22/700、28/700，其余 600 与 400 拉开，用于营销型首页。

## 5 图标风格标准

全局不变量：**控件图标（标签栏、导航、菜单、按钮、工具栏、表格、表单）永远是 2px 线性矢量**，16px 时 1.75；一物一图；同一对象各处同一图标。可选的是入口图标、空状态、主视觉装饰的风格。

| 包 | 用在 | 构造 | 规则 |
|---|---|---|---|
| `line` 线性 | 控件、入口、一切场合 | 24 栅格、描边 2px、圆角端点与圆角转折、单色（ink2 → 选中 brand.text） | 默认包；关键线对齐；4 档尺寸 16 / 20 / 24 / 32 |
| `duotone` 双色 | 入口图标、空状态、权益 | 与 line 同一条路径；闭合主体填 brand.tint，细节线用 accent，描边仍是 2px | 不用渐变；浅底只用 tint 阶；一格最多两色 |
| `clay3d` 软陶 | 入口图标、空状态、结果页、引导页（**不用于控件**） | 生成图 4×4 拼板切图，透明 WebP 240px，哑光、左上单光源、每物体不超过三色、同一风格块 | **待裁定**：现行风格矩阵里黏土只允许空状态与主视觉装饰，入口图标需归入轻拟物或由用户放宽；同组只用一种做法 |

检查（见 §7）：同一页面不混用两个入口图标包；控件图标描边一致；入口图标与标题的比例（`interface-icons` 卡）；`clay3d` 不得出现在控件位置。

## 6 风格包：可拆开、再搭配

一个“风格”是六个选项的组合。每个选项都有规范内的取值，以及标“待裁定”的扩展取值：

| 轴 | 取值 | 备注 |
|---|---|---|
| 配色 `palette` | `themes.json` 里任一主题（25 套），含深色映射 | 总是合规：由 `check_contrast.py` 保证 |
| 图标 `icons` | `line` / `duotone` / `clay3d` | `clay3d` 待裁定 |
| 形状 `shape` | `tight` 2/4/8/12（待裁定）/ `standard` 4/8/12/16（现行）/ `round` 6/10/16/20（待裁定） | 圆角种类 ≤ 4 |
| 层级 `depth` | `hairline` 发丝线 / `soft` 五级阴影（现行）/ `glass` 毛玻璃 | `glass` 只限主视觉装饰与入口图标块；用于导航、标签栏、弹层需裁定；文字落在玻璃上按最差背景 ≥ 4.5:1 |
| 字阶 `type` | `standard` / `compact` / `bold` | 见 §4 |
| 动效 `motion` | `calm` / `snappy` / `friendly` | 只改时长偏向，令牌不变；见 `motion-recipes.md` |

搭配规则由 `audit_theme_discipline.py` 的 `check_combo()` 判定，返回 `errors`（硬违规）、`needs_ruling`（待裁定）、`notes`。`make_style_lab.py` 生成的“风格实验室”页面用同样规则实时给出标记。

### 三套预设（实验室的起点，用户可以逐项改）

| 预设 | 配色 | 图标 | 形状 | 层级 | 字阶 | 动效 | 适合 |
|---|---|---|---|---|---|---|---|
| A 花艺杂志 | florist | line + clay3d（入口） | standard | soft | bold | calm | 零售、礼品、生活方式 |
| B 石墨效率 | b2b-graphite | line + duotone（入口） | standard | hairline | compact | snappy | 后台、工具、数据 |
| C 清透航旅 | travel-azure | line + duotone（入口） + glass 装饰 | round（待裁定） | glass（仅装饰） | standard | friendly | 旅游、健康、家居 |

## 7 审计脚本矩阵（什么时候跑什么）

| 阶段 | 脚本 | 查什么 | 状态 |
|---|---|---|---|
| 选主题 | `check_contrast.py` | 单主题对比度、深色映射、阴影、色阶单调 | 已有 |
| 选主题 | `audit_theme_discipline.py` | 色阶质量、色相家族、色相预算、区分度、色觉差异、面积与层级、深色配套、**搭配兼容** | 新增 |
| 选参考 | `teardown.py` | 参考页的字阶、色板、圆角、阴影、间距网格、对齐线、留白，以及体检提示 | 新增 |
| 导出 | `export_tokens.py --check` | 令牌文件格式与双模式取值 | 已有 |
| 做完页面 | `audit_rendered.py` | 字号、字重、对比度、触控、聚焦框、组件库、`transition: all` | 已有 |
| 做完页面 | `audit_palette.py` | 渲染页的色相是否都属于主题 | 已有 |
| 做完页面 | `teardown.py --lint` | 对自己的页面做审美体检 | 新增 |
| 交付前 | `check_document.py` | 文件级规则 | 已有 |
| 建议新增 | `audit_tokens_usage.py` | 渲染页的计算值有多少落在令牌里（目标 ≥ 95%） | 提议 |
| 建议新增 | `audit_icons.py` | 描边宽度一致、同一入口不混包、控件位置没有 3D 图 | 提议 |
| 建议新增 | `audit_motion.py` | 时长与曲线是否取自令牌，是否有 `will-change`、`transition: all`、减少动态效果分支 | 提议 |

## 8a 现状审计结果（2026-11-04，`audit_theme_discipline.py` 跑 25 套主题，themes.json 未改动）

全库没有 FAIL；WARN 与 INFO 如下，**只报告，没有改任何主题**，改不改由用户裁定。完整明细在会话 `raw` 下的 `theme-discipline.md`。

| 发现 | 范围 | 含义 | 建议 |
|---|---|---|---|
| 成功色 `#18794E` 与危险色 `#C93644` 在红绿色盲模拟下 ΔE ≈ 7.6（低于 8） | 25 套共用的状态色 | 红绿色盲用户难分“成功/失败”；状态不能只靠颜色 | 状态一律带图标或文字（现行已要求）；若要彻底解决，把成功色向青绿偏 10°–15° 或加深一阶，再跑 `check_contrast.py` |
| 浅底阶（actionTint）在页面底（canvas）上几乎看不见（ΔE < 3） | 11 套，最低的 civic-red 0.61、violet-academy 0.80、wine-jewel 0.93 | 选中态的浅底在页面上分辨不出 | 选中态同时加主色文字与左侧强调线（现行小程序分类已这样做）；或把这些主题的页面底改为中性灰 |
| 主色与价格红、危险红色相重叠（< 20°） | xiangcai、civic-red、sichuan-hotpot、fast-noodle、fitness-gym 等 5 套 WARN，另有 3 套 INFO | 品牌红与价格红、危险红混淆 | 价格与危险处必须带“¥”或图标；或这些行业改用不含红色的点缀组合 |
| 导航底 navBg 偏染色（彩度 > 0.03） | 7 套（如 xiangcai `#F0DCC8`） | 页面顶部偏色，抢主色 | 导航底改用主色浅底第 1 阶或白底 |
| ai-agent 的 10 阶色阶亮度步幅不均（最大/最小 3.0，阈值 2.2）；色相簇 8 个（模块点缀色占 3 个） | 1 套 | 色阶中间两阶太接近；模块点缀色让色相预算超出 | 重排 2–3 阶亮度；模块点缀色只用于一级模块 |
| coffee 主色与点缀色色相只差 10°；fitness-gym 主色与点缀色在红绿色盲下 ΔE 3.3 | 各 1 套 | 点缀色失去作用 | 点缀色改取邻近色 25°–60° |

脚本局限：色阶质量检查只覆盖有 `scale` 的主题（目前只有 ai-agent）；严重度分级与 8° 之类的阈值是经验值，可由用户裁定；玻璃的 tint 不透明度是假设值。
