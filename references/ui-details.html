界面细节规范

适用范围

产品前端（小程序、网页后台、网站、智能体界面）及其原型里，图标（含生成的色块图标与饱和度上限）、背景（页面底、卡面、浮起面的分层）、卡片家族的外观与构图细则。承接设计路径的 P6 阶段，填它留下的三处“细则待补”；功能、内容与点击去向归系统技能，页面怎么排归页面范式库，具体数值回到视觉设计规范；数据在 references/ui-details.json，检查用 scripts/check_icon_image.py 与 scripts/ui_details.py。

工作流程

  1. 接力：P4 定令牌，P5 定组件库，本页用在 P6，与 P7 可并行。
  2. 做的次序：背景（三层令牌与分层检查）、卡片家族（几种、谁是主角、整卡去哪）、图标（哪些对象要哪一类）、生成图标并验收；下面阅读次序是图标、背景、卡片。
  3. 每一类先答“选用前要问的问题”，BRIEF 留一行理由，再查表；表是词汇，句子由你按产品写。
  4. 检查：check_icon_image.py 查图标颜色，ui_details.py layers 查分层、grid 算列数，audit_rendered.py 查渲染；浅深各一遍。
  5. 结束前写偏离说明，用 experience.py note 沉淀，写进 BRIEF 的“本次沉淀”。

核心规则

一、先分清功能和视觉

边界见 references/ui-ownership.md：系统技能决定有什么、做什么，本技能决定长什么样。图标：哪个功能需要图标归系统，画法、颜色与饱和度归本技能；卡片：承载什么内容、整卡去哪、卡里有哪些操作归系统，构图、圆角与阴影归本技能；背景：外观设置放哪一页归系统，分层与浅深两套归本技能；配图：哪些对象要图归系统，风格与比例归本技能。排不下就退回，不自行增删；冲突时功能先于外观。

颜色与饱和度阈值

用 HSB（即 HSV）的饱和度 S，0 到 1：设计师在取色器里说的饱和度就是它；不用 HSL 的 S（近白近黑处会虚高）。统计范围：只统计不透明（透明度 ≥ 128）、非近白（V ≥ 0.97 且 S ≤ 0.05）、非近黑（V ≤ 0.12）的像素，按面积加权。指标四个：均值 S、第 90 百分位 S、S 大于 0.80 的像素占比、主色相个数（S 不低于 0.15 的像素按 10 度分箱，峰值正负 20 度并为一个，不足 5% 的不计）。

指标起始上限（本技能取值）命令行参数超限怎么修
均值 S不超过 0.45--max-mean图形色换成更浅的一阶
第 90 百分位 S不超过 0.65--p90降低大片深色的饱和度或缩小面积
S 大于 0.80 的像素占比不超过 3%--hot-share，临界值 --hot-s去掉纯色高光与荧光色
主色相个数不超过 2--max-hues只留主色相和一个邻近色

只管图标；商品、门店、环境照片等配图不受限。检查切开后的单个图标，不是 4×4 拼板。本技能取值，待样板图校准：16 份资料没有一份给出饱和度数值，只有“饱和度较低的邻近色系，不要太过扎眼”这句定性话。

控件图标不看饱和度，只看是不是令牌色。矢量色块图标里令牌色不计饱和度（视觉规范的双色描边取按下阶），自造色才判；位图分不出令牌，一律判，所以生成图的图形色要比品牌阶浅。深色版按彩度 C（V 乘 S）度量，与浅色版比 P90。

图标色板与提示词

品牌阶的 S 在 25 个主题里中位数 0.78、最高 1.0，直接画图形会超“S 大于 0.80 占 3%”。色板由主题推导，写进提示词：

色板浅色深色
底块令牌 actionTint令牌 dark.actionTint
次层品牌阶色相，S 0.28，V 0.98（相当于主色 15%–30% 浓度，交付为实色）底块与图形按 65% 比 35% 混合
图形品牌阶色相，S 0.58，V 0.88令牌 dark.actionText
线稿品牌阶色相，S 0.62，V 从 0.60 往下取到对底块 3:1令牌 dark.actionText

S 不超过品牌阶自己的 S。命令：check_icon_image.py --palette 主题 id。本技能取值，待样板图校准。

可粘进 Imagegen 提示词（接在共用风格块后，十六进制色用 --palette 输出替换）：

Colour constraints for this icon set. Use a soft, low-saturation pastel palette built from ONE hue: a light tint base, a slightly deeper second layer and one figure colour of the same hue, plus neutral off-white or grey only. Use only these colours: base {base}, second layer {mid}, figure {figure}, outline {line}. Keep every colour at or below 65% HSB saturation; nothing neon, fluorescent or candy-glossy; no second accent hue. Flat two-layer shading: no gradient highlights, no specular white spots, no glow, no hard drop shadow. No text, letters or numbers. Transparent background, clean anti-aliased edges, no halo, centred with about 12% padding.

风格块选了软陶或 2.5D 时，把“无渐变高光”改成“高光只用同色相更浅一阶”，上限不变。提示词只能引导，出图后必须用脚本验收；商品与门店照片不套这一段。

校准：用户说还是太艳或太淡时改哪个数

  1. 取样：认可的 3 张、被嫌太艳的 3 张，都是切开后的单个图标，分放两个目录各跑 check_icon_image.py --json。
  2. 定线：让认可的全过、太艳的至少拦住 2 张，先看 P90 与均值，线下留 0.03。
  3. 三处同步：脚本、数据文件、本页；experience.py note 更新 icon-saturation-threshold-skill-value。
  4. 一次只动一个数，改完再跑这 6 张。

三、背景

三层分层，全取令牌

层用在哪里浅色深色
页面底 canvas最底层、卡片间隙；层级 0，无阴影中性浅灰或主色极浅底（亮度 ≥ 0.85）dark.canvas，最暗，不用纯黑
卡面 surface卡片、列表组、输入区；层级 1，发丝线加第 1 级阴影白（shared.surface）dark.surface，比页面底亮
浮起面悬停（第 2 级）、下拉与吸顶（第 3 级）、对话框（第 4 级加遮罩）仍是白，靠阴影与 scrim卡面混入白 5%、8%、11%（surfaceMix），配白发丝线
浅底块与品牌主卡底卡内分区、选中项、状态条、图标块的底；品牌主卡每屏一张actionTint、accentTint、状态 Tint；品牌主卡 action 实色白字dark.actionTint 等；主卡 dark.action 配 onAction

分层检查量

量页面底与卡面的明度差 ΔL*（CIE L*，卡面减页面底）。浅色不低于 1.5，深色不低于 4，小于 3 时卡面必须带发丝线承担分层。25 个主题实测：浅色 1.7–4.4（石墨最低，靠发丝线），深色 5.5–6.1。本技能取值；资料没给过页面底与卡面的对比度与层数。命令：ui_details.py layers --all；再眯眼看一屏，三层仍分得出。

五类用法

用法要点与做法选用前要问的问题可以有个性的地方
页面分层与安全区
bg-layers
must		取三层令牌，分层按序：间距、色差、发丝线、阴影。静止同屏不超过三级；底色延伸到屏幕边缘，底栏不透明并加安全区。1. 这一块在哪一层？靠什么与相邻层分开？
2. 我是在分层，还是只想加个底色？		页面底在浅灰与主色极浅底间选。不动：三层、令牌。
区块背景
bg-blocks
default		分组靠间距，品牌主卡与营销区各有固定底色。同组卡片共用间距，不加底；区块之间用间距不用线；营销浅底 accentTint 配 accent 文字，同屏不超过 2 个营销模块；状态条用状态 Tint 加图标。1. 这几块是同类还是不同类？同类用间距，不同类才换底。
2. 这块底色在说明什么含义？说不出就不换底。		间距节奏、营销浅底出框、图形化标题。不动：主卡每屏一张。
空状态、结果页与加载
bg-states
default		沿用 canvas，不另设背景。整页沿用 canvas，卡内沿用 surface；插画居中，下面一句话和一个操作；加载骨架用 surface 上的同形灰块（line 或 photo），与真实内容同高。1. 用户下一步该做什么？插画是陪衬，操作才是主角。
2. 骨架和真实内容同形吗？		插画叙事与角色、一句话的语气。不动：沿用 canvas、有下一步。
背景图、遮罩与渐变纹理
bg-image
must		背景图只给沉浸式首屏与营销头图；压图文字必须有遮罩。同屏至多一张，功能页不铺图；遮罩起点：黑色透明度 20%–45% 或白色实底；背景不用渐变与纹理。1. 这张图帮用户认出什么或决定什么？只是装饰就不放。
2. 压图文字最亮的那一处，对比度量过吗？		取景与调色、承载块形状、头图出框。不动：遮罩加对比度、无渐变纹理。
深色背景
bg-dark
must		取 dark 映射，另一套色板，不是浅色取反。页面底最暗，卡面更亮，浮起面逐级更亮；阴影只作辅助；白底图略压暗；浅深各验收一遍。1. 这一层在深色里取哪个令牌？
2. 图标与插画换成 dark 映射的色了吗？		底色相偏冷或偏暖、品牌色亮度。不动：映射令牌、对比度、层级顺序。

四、卡片家族

先判断该不该用卡片

适合：用户在浏览而不是搜索、内容异质、每条可独立阅读并有指向详情的摘要。不适合：同质内容要逐项比较（用列表或表格）、同类图片集合（用图片网格）、要快速扫标题。代价：卡片弱化排序、不易扫读、占空间，一屏条目更少。整卡可点、点击区与悬停的行为见系统技能规则卡 interaction-patterns。

栅格怎么排

推导见视觉设计规范“前端排布的推导”：列数 = 向下取整（（容器宽 + 间距）÷（最小卡宽 + 间距））；写成 repeat(auto-fill, minmax(最小宽, 1fr))，不写死列数；卡数固定要铺满时用 auto-fit。小程序双列商品卡最小宽由 320 屏推出：（320 − 2×12 − 8）÷ 2 = 144，取 136，使 320–430 宽恒为两列；取 160 时 320 屏掉成一列。命令：ui_details.py grid --min 160 --gap 12 --width 375。

五、怎么用

  • 强度三档：must 违反即退回；default 可偏离，须写偏离说明（规则 id、为什么、风险、怎么验证），用 py -X utf8 scripts/ui_details.py deviation <规则 id> --why … --risk … --verify … 生成；hint 按情境取舍。
  • 证据分五类：规则（官方、研究机构）、实例（博客，数值不当规则）、用户要求、惯例（无来源）、技能内部（含视觉规范既有数值与本技能取值）；资料没覆盖的写出来，不编来源。
思考链按这个次序问
图标1. 需要图标吗？系统技能定，没有合适图形宁可不放
2. 属于哪一类：控件、入口图标块还是装饰？
3. 颜色从哪来：控件取令牌，入口块取 tint 加色板，装饰取插画面
4. 产品里已有它的图标吗？沿用并登记
5. 先过脚本，再看四态与深色；超限改提示词
背景1. 这一块在哪一层？
2. 和相邻层靠什么分开：间距、色差、发丝线、阴影？
3. 压着文字或图吗？压图要有遮罩
4. 深色里它是哪个令牌？
5. 删掉它，用户少认出什么？少不了才加
卡片1. 该不该用卡片：浏览、异质？要比较就用列表
2. 哪个家族？谁是主角？
3. 字段来自系统技能的清单；同一事实只说一次
4. 整卡去哪？一卡一个主按钮
5. 状态画齐了吗？
6. 列数由最小卡宽算出，不写死
7. 个性放在哪一点？计入记忆点预算

质量门禁

  • 退回修改：控件图标用了位图或令牌以外的颜色；生成图标没过 check_icon_image.py（含深色对照）；页面底与卡面 ΔL* 不达标且无发丝线；卡里套卡，或整卡可点又放同目的地按钮；卡片圆角超过 4 种；偏离 must；default 被偏离却没有偏离说明。
  • 不得交付：没有 detail-system.md；浅深没各检一遍；图标没有映射表；资料没覆盖的数值被写成有外部来源。

命令：py -X utf8 scripts/test_check_icon_image.py；test_ui_details.py；check_icon_image.py <图标目录> --theme <主题 id>；ui_details.py layers --all；check_document.py references/ui-details.html。

交接规则

  • 交给开发技能：图标资产清单（文件、尺寸、色板、来源与许可）、对象到图标名的映射表、卡片家族表与最小卡宽、状态清单；数值只取令牌文件，本页不新增令牌。
  • 交回系统技能：卡里内容放不下、需要更多操作、缺状态词的退回清单；项目模式走需求变更台账。与页面范式库、设计路径冲突的，写进 BRIEF 待裁定清单，不自行改它们。
  • 结束前用 experience.py note 沉淀新偏好、规则纠正、阈值校准结果（key icon-saturation-threshold-skill-value）。
