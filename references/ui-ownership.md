# 界面职责划分：功能归 Luz-System，视觉归 Luz-Design

适用于所有产品前端（网页管理后台、小程序、手机网页、网站、智能体界面）和它们的原型。七个技能的 SKILL.md、规则页和项目阶段表都以本页为准，各处的摘要与本页冲突时改摘要，不改本页。

## 一句话

Luz-System 决定界面里**有什么、做什么、怎么走**；Luz-Design 决定这些东西**长什么样、怎么排、怎么动**。

同一个页面，System 写清它有哪些入口、标签栏有几项、用哪些组件、每个按钮做什么；Design 把这些画出来：构图、卡片、按钮的样子、图标、配图、动效、主题。

## 对照表

| 事项 | Luz-System 决定（功能） | Luz-Design 决定（视觉） |
|---|---|---|
| 页面与入口 | 有哪些页面与路由；每个功能的类别（核心、信息、营销、辅助）和唯一入口归属（标签栏、首页、个人中心、页内）；每个入口去哪 | 入口怎么排、图块的样子 |
| 首页 | 首页要承载哪些功能（来自功能清单与入口归属）；首页上的功能点了以后做什么 | 首页的布局范式与组合（金刚栅格、单列、双列卡片、瀑布流、信息流、便当网格、顶部标签、沉浸式）；分成哪些模块、每个模块放哪些功能、先后顺序；精简与去重：同一目的地在首页只出现一次，标签栏已有的不再在首页重复；入口怎么排、几列几行 |
| 标签栏与导航 | 标签栏几项、叫什么、顺序、默认项、哪些页面显示；侧栏菜单分几组、层级关系；返回规则 | 标签栏的高度、图标图形、选中样式；侧栏的宽度与分隔；导航栏的样子 |
| 组件 | 用哪些组件承担哪个任务（表格、筛选、表单、对话框、步骤……）；它们的行为、状态、键盘操作、可访问名称 | 选哪个组件库、主题怎么接；组件的外观、尺寸、圆角、颜色 |
| 按钮 | 哪个动作放按钮；一个动作一个按钮；文案（动词加对象）；何时可用、何时禁用并写什么原因；点了以后的结果、反馈、确认与撤销；谁有权限；这页的主动作是哪个 | 主、次、危险按钮长什么样；尺寸、圆角、图标选哪个图形；悬停、按下、禁用、加载的外观 |
| 卡片 | 卡片承载哪些内容、按什么顺序；整卡点了去哪；卡里有哪些操作 | 卡片的构图与层次；圆角、描边、阴影；卡内图文的比例与对齐 |
| 列表与表格 | 有哪些列、默认排序与视图、筛选项、分页方式、批量操作、导出范围 | 列宽、对齐、行高、表头样式、斑马线、密度 |
| 图表 | 回答什么问题、用哪些指标、按数据关系选哪类图、数据少时怎么降级 | 配色、线宽、网格、提示框、图例的样子 |
| 图片与插画 | 哪些对象要有图（商品封面、门店照片、空状态配图的位置）；图缺失时的降级 | 图的风格与内容、实拍还是生成、比例与裁切；插画与封面 |
| 图标 | 哪个功能需要图标；一个对象一个图标（含义不重复） | 图标集、线宽、双色块、尺寸、选哪个图形 |
| 动效 | 哪个操作要有反馈；变化不许让周围内容跳位；可撤销的时限；减少动态效果下保留什么 | 动画的形态、时长、缓动、转场、骨架与加载的样子 |
| 响应式 | 窄屏上哪些功能保留、哪些收进“更多”；手机上必须能完整操作 | 断点、栅格、列数、间距、各档怎么排 |
| 主题 | 有没有外观设置、放在哪一页（例如账号菜单） | 浅色与深色两套取值、对比度、切换时不闪不跳 |
| 文案 | 按钮、提示、状态的文案键表与含义 | 字体、字号、行高、字重（文风归 Luz-Writing） |
| 原型 | 动作编号、页面编号、状态与演示数据、场景配置面板、减少动态效果开关 | 原型的全部外观：组件库、主题、配图、动效 |

## 交接物

**System 交给 Design 的是“界面功能说明”**：页面清单与路由、入口、标签栏项数与名称、每页的组件清单与用途、动作表（动作编号、按钮文案、触发与禁用条件、结果与反馈、确认与撤销、权限）、状态、数据需求、文案键。项目模式里它是系统架构文档的前端页签；独立会话里它是架构与系统设计网页。里面不出现颜色、字号、圆角、阴影、图标图形、图片内容、动画时长和栅格数值。

**System 交给 Design 的还有“入口表”`entrances.json`**：每个前台功能一行，由 System 在架构阶段随功能说明一起交出，Design 据此决定首页的模块、顺序与去重，不增删入口。字段：`fn`（功能编号，对应功能清单）、`name`（界面上的入口名称）、`type`（功能类型：`context`、`search`、`task`、`status`、`account`、`order`、`marketing`、`content`、`tool` 九类之一）、`category`（`core`、`info`、`marketing`、`aux`）、`entry`（唯一入口归属：`tab`、`home`、`mine`、`context`、`in-page`）、`destination`（目的地，页面编号或路由加参数）、`freq`（`high`、`mid`、`low`）；可选 `image`、`limited`、`summary`，另可带 `tabbar`。格式细节以 `py -X utf8 scripts/page_pattern.py show entrances_schema` 为准；System 一侧用 `entrances_check.py` 检查。入口归属是功能，归 System；首页放哪个区域、同一目的地不重复出现，是版面，归 Design。Design 发现入口表有缺或有冲突时，写进 BRIEF 的退回清单交还 System，不自行补入口。

**Design 交出去的是“视觉规范”**：所选组件库与主题、设计令牌文件（`export_tokens.py`）、视觉板、原型的外观、图标与配图的资产清单、动效令牌与场景表。开发技能按它实现。

**原型**：行为、数据和场景由功能说明规定；外观、组件库和动效由视觉规范规定。项目模式里原型和前端界面设计文档由 Design 阶段交付；独立会话里视觉板和原型的外观部分按 Design 的规则卡产出。

## 两条不许越过的线

1. **System 不选视觉**。规格里只写“需要什么”（“商品卡要有封面图”“标签栏 4 项”“这个按钮在库存为 0 时禁用并写原因”），不写颜色、字号、圆角、阴影、描边、图标图形、配图内容、栅格与间距、动画时长与缓动。规则页里需要这些数值的地方，写“见视觉设计规范某节”。
2. **Design 不改功能**。页面、入口、标签栏项数与顺序、组件有无、按钮有无及其动作、流程、状态、文案键，Design 只能照做。画不下、排不下时，不自行增删，退回 System 提变更（项目模式走需求变更台账）。

冲突时功能先于外观：外观让某个功能不可用，保留功能，换一种外观。

## 容易划错的几处

- **时间**：提示 3 秒后消失、删除后 5 秒内可撤销、加载超过 1 秒才出骨架、点击 0.1 秒内要有反应，这些是行为，归 System；动画跑多久、用什么缓动，是视觉，归 Design。
- **可访问**：键盘能到、角色与状态、可访问名称、悬停内容的触屏替代，归 System；焦点框的样子、触控目标的尺寸、文字对比度的取值，归 Design。
- **主动作**：这页的主动作是哪个，是功能优先级，归 System；它画成实色主按钮，归 Design。
- **窄屏**：手机上还能不能做完这件事，归 System；怎么排，归 Design。
- **头像**：有没有头像位、没头像时是否显示默认头像，归 System；头像怎么画，归 Design。
