# 表格文件模板

十个表格版式模板和十一个可复用块。每个模板有一份描述文件（`specs/`，是 `make_xlsx.py` 的合法输入）和一份由它渲染出的样例（`samples/`）。样例用虚构门店“花间集”的数据，只有版式参考价值，不是客户成品。

版式是硬规定，模板不能放宽：宋体、正文 12 磅、标题 16 磅粗体居中、文字全黑、淡色底区分类别、细黑边框、关闭网格线、无序号列、分组名纵向合并、一格一个事实、冻结表头与分组列、A4 一页宽并重复表头、页脚“第 N 页 / 共 N 页”。全部规则见 `context.py xlsx` 规则卡。

## 命名

`DC-XL-三位序号-中文名.xlsx`，描述文件同名 `.json`。可复用块编号 `DC-XL-P01` 起，文件在 `specs/parts/`。清单与块的登记见 `manifest.json`。

## 怎么换内容

1. 复制对应的描述文件，改 `title`、`sheet`、`columns`、`rows`；`manifest.json` 里每个模板的 `fields` 列出要改的字段。
2. 分组列写 `group_by`（大组在前），生成器自动前置、排序、纵向合并；不要手写序号列。
3. 类型、状态这类标签列写 `tags`；可选或新增行用 `highlight`；整行淡色底用 `tint_by`。
4. 单价、金额、预算、折扣、工时只来自人工提供的报价单。报价单与预算表的数字格留空（极浅米黄的填写格），金额、差额、执行率用公式，填入前显示为空；智能体不得自拟任何数字。`quote_evidence` 里的要求人和原话必须换成真实的人和原话，写了才放行这些列。要把报价数字一并写进文件时，改用 `estimate` 块并补 `provided_by` 与 `evidence`。
5. 日期、金额之外的数字也按真实数据填写；样例里的数量、库存、订单号、周次安排都是虚构值。

## 怎么生成

正式命令：

```
py -X utf8 scripts/make_xlsx.py <spec.json> <输出.xlsx> --session <会话目录>
```

它需要 Design 会话与前置检索门禁（`crawl_preflight.py`），写完自动检查并登记哈希。**正式交付必须走正式命令与门禁。**

本库的样例不走门禁：`tools/build_excel_samples.py` 直接调用生成器的内部渲染函数 `_render_workbook`，再用 `tools/xlsx_decorate.py` 补数据验证、填写格底色与条件色块，最后跑 `check_document.py`。

```
py -X utf8 templates/documents/excel/tools/build_excel_samples.py [--only DC-XL-001]
```

## 怎么检查

- `py -X utf8 scripts/check_document.py <样例.xlsx>`：零 ERROR。报价单与预算表加 `--allow quote`，确认表加 `--allow multi-sheet`。
- 用 openpyxl 读回：字体全是宋体、字号全是 12 磅（标题 16 磅）、文字全黑、边框全是细线、冻结窗格、合并只有标题、合计标签和纵向分组、筛选范围与数据区一致、A4 一页宽并重复第 3 行。
- 用 WPS 表格打开导出 PDF 看版式：标题居中、表头蓝灰底、类别淡色底、分组名合并居中、换行单元格完整、页脚页码。

## 已知限制

- `make_xlsx.py` 不支持数据验证、填写格底色和条件色块，样例靠后处理补上。正式流程里生成器写完文件就登记哈希，事后再改文件会使登记失效，所以这三项要并入生成器的渲染函数后才能走正式交付。
- 规则卡写了“要继续筛选排序的表不合并，每行写全分组名”，但 `check_document.py` 对未合并的连续重复首列照样报错，没有例外开关。DC-XL-009 靠订单按到达顺序排列、首列不连续重复来通过；按门店排序的导出表现在只能合并。
- 公式由 WPS 或 Excel 打开时计算，openpyxl 写出的文件没有缓存值；填入单价前金额、合计、差额、执行率显示为空。
- 生成器按保守估算行高，分组列里单独成行的最长值会被估成两行高，样例数据已避开。
- 排期表周格里的“计划”“进行”“完成”是约定写法，条件色块按这三个词上色。
- 样例中的门店、商品、订单、设备、库存与周次安排均为虚构，不含日期，不含单价与金额。
- 版式只在 WPS 表格里导出 PDF 查看过，没有在微软 Excel 里核对。
